# 岩笋 v0.1.7

一句话：这一版开始能装「脚本类 mod」了，顺手把「有新版本」做成一键换。

## 新增

**1. 脚本类 mod 能装了**

有些 mod 不是数据包（`.pak`），而是一段跑在游戏里的代码。以前这类包装进去游戏也不认，现在会：
- 从 UE4SS 官方地址下载 `3.0.1`，核对指纹（写死在程序里）后才解包，不核对不放行；
- 按 UE4SS 的约定放到 `FSD\Binaries\Win64\`（`UE4SS.dll`、`dwmapi.dll`、`UE4SS-settings.ini`、`Mods\` 四样）；
- 装 mod 时识别 `main.dll` / `main.lua` / `main.js`，落到 `Binaries\Win64\Mods\<名字>\`（和上面四样同一个平铺根目录），不进数据包合并；
- 背包里标出「脚本类」，并告诉你是「已生效」「还没验证」还是「没生效」——没生效会写明原因（比如「它缺一个运行库」）。

**2. 一键换新版**

「今天」页的「有新版本」现在可以直接换：
下载新包 → 核对大小 → 合并 → **合并成功才**写安装记录、删旧文件。任何一步失败都保留旧版，提示里明说「没换成，旧版还能用」。
装了好几个的话，可以点一次「全部更新」。

**3. 设置页写清楚三件事**（UE4SS 卡片下面，固定显示，不用点开）
- 我们装的是官方 UE4SS 3.0.1；
- 有些 C++ 脚本 mod 是为别的 UE4SS 版本编的，装进去会提示「缺一个运行库」，那不是安装坏了；
- 我们不会拿别人改过的 UE4SS 当自己的发行依赖。

## 关于 UE4SS，装之前值得知道

- **它是什么**：一段注入游戏进程的脚本加载器，装在游戏的 `Binaries\Win64` 里，只影响这台电脑。
- **游戏里看不见它管的东西**：这是正常的——游戏自带的 mod 列表是另一套系统。
- **只能从这个程序里卸**：卸载会把原来那套（如果你之前装过别的启动器的）原样放回去；如果你之前是干净的，就删干净，不留垃圾。
- **会动游戏目录的哪些文件**：`Binaries\Win64\` 下的 `UE4SS.dll`、`dwmapi.dll`、`UE4SS-settings.ini`、`Mods\`。装之前会先把现有的同位置文件备份到我们自己的数据目录（`backup\ue4ss-<时间戳>\`），卸载按备份还原。
- **联机**：DRG 官方只认它自己那套 mod 体系，注入类的改动不在它的名单里。你想在联机时用不用，自己决定。

## 修复

- 脚本包只有一层 `Scripts\` 目录时，会被多剥一层，导致装进去的 `main.lua` 位置不对；
- 背包里所有脚本 mod 共用同一个状态，装了两个就互相盖。

## 已知限制

- **令牌可能被吊销**：mod.io 的访问令牌会过期或被吊销（这版开发期间就遇到过一次）。遇到时按提示重新打开 https://mod.io/me/access 生成一串，粘回设置页即可。
- **有些 C++ 脚本 mod 提示「缺一个运行库」**：这些 mod 是为别的 UE4SS 版本（比如别的启动器用的那套）编译的，缺它自己的依赖。官方 UE4SS 跑不起来它们，这不是安装坏了，也不是我们能修的。
- 一键升级只对**从 mod.io 装的** mod 生效；自己导入的本地包没有在线版本可比。
- 游戏内 mod 列表看不到 UE4SS 管的东西，属正常现象。
- 装机流程在 v0.1.5 / v0.1.6 验过，这一版没有在全新的 Windows 上重跑。
