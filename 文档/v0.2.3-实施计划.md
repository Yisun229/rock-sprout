## §3 里程碑

### M0 · 名字表补名（0.5 天，已开工）
- 抽 StringTable（路径在四张表的 `$open` 里），把皮肤 / 十字镐 / 喷漆三张表的名字补上
- 顺带查两个差异：① 皮肤 654 vs 旧表 280，差的 374 条是什么；② 超频 368 条里 193 条无名，是「本来没有本地化键」还是「locres 漏查」（**结论只记进文档，不扩范围**）
- **报三个数**：每张表 **抽出 N / 能配上名字 M / 配不上 K**
- **配名率低于一半就停下来报数**，不要自行决定怎么降级

### M1 · 模组稀有度（0.5 天）
- 从 pak 抽改装的稀有度字段，接到 `upgrades.json` 578 条上（现在 `tier`/`requires` 全 null，**这一版只补稀有度，不补层级与前置**）
- 抽屉改装清单每行标稀有度（文字或色点，不引入新配色 token）
- 验收：抽到多少条报多少条，配不上的写「稀有度未知」并计数

### M2 · 皮肤与喷漆（0.75 天）
- 抽屉加「外观」分段：列出该武器/护甲的皮肤与喷漆，已拥有的正常显示、未拥有的灰掉；**只列名字不做图**
- 降级（决策 7）：配名率不足 → 只列已拥有的
- 验收：本机 25 个有皮肤的物品逐个点开能列出名字；配不上的显示 `#id` 前 8 位并计数

### M3 · 十字镐（0.5 天）
- 装备页底部一块：19 个已解锁部件按 `part`（Blade / Head / Shaft / Grip / Paintjob）分组；不显示当前装配
- 验收：与存档 19 个逐个对得上

### M4 · 回归与出包（0.5 天）
- 回归至少 5 条新场景 + 版本号 0.2.3 四处 + 安装包与便携包 + 发布说明
- 验收：默认跑法全过；三句话如实写进发布说明（见 §6）

**合计 2.75 天**（M0 0.5 + 稀有度 0.5 + 皮肤 0.75 + 十字镐 0.5 + 出包 0.5）

## §5 风险

| 风险 | 触发条件 | 应对 |
|---|---|---|
| StringTable 抽不出来 | 资产路径与 `$open` 记的不一致 | 三张表继续只有 ID，M2/M3 降级为只列已拥有的 |
| 皮肤配名率过低 | 654 条里能配上 < 300 | 停下来报数，由计划侧决定是否只列已拥有 |
| 稀有度字段不在改装的单独资产上 | 需要从父资产继承 | 只报「已抽到 N 条」，其余标未知 |

## §6 发布说明必写三句

1. 皮肤与喷漆只显示名字，没有图片；
2. 模组只补了稀有度，层级与前置关系留下一个版本；
3. 十字镐只列已解锁部件，不显示当前装的是哪几个。
