# 岩笋 · Rock Sprout — v0.2.x 功能清单与版本切分（PRD）

> 版本：2026-11-03 定稿
> 定位：这份文件回答「伴侣线到底要做哪些东西、每样东西的数据从哪来、各排在哪个版本」。
> 上游是 `路线图-v0.1到v1.0.md` §6；下游是每个版本的 `v0.2.x-实施计划.md`。
> 排期依据：用户 2026-11-03 的三轮质询答复（q1–q6 + Q1–Q3）。

---

## §1 一句话定位

**把存档里已经存在、但游戏界面上看不到或不好查的数字，用一个页面对准它摆出来；不写档、不联机、不替玩家做决定。**

判断一条需求要不要做，只问三句：

1. 这个数**存档里有没有**？（有 → 可做；没有 → 看能不能靠公开结构表推；推不出 → 不做）
2. 玩家**打开程序想不想看**？（不想看 → 不做，哪怕能做）
3. 做出来**会不会让人以为我们在改他的档**？（会 → 改成只读并写明，或者不做）

## §2 数据来源分三类

| 类别 | 含义 | 可信度 | 版本 |
|---|---|---|---|
| **存档直读** | 解析 `.sav` 直接拿到的值 | 最高，就是玩家自己的数 | 先做 |
| **存档 + 结构表** | 存档只存 GUID/编号/等级数，需要一张人工核对过的对照表才能显示成人话 | 高，但表错了会显示错 | 中间 |
| **联网** | Steam 商店 / 在线人数 / 成就 / 好友 | 中，外部依赖，无 key 时整块隐藏 | 垫底 |

**结构表是这条线最大的隐性成本**：它不是代码，是「从社区 wiki 抄下来、再逐条核对」的数据劳动。

## §3 功能全表

### 3.1 我的矿工（v0.2.1）

| 项 | 能看到什么 | 数据来源 | 缺什么 |
|---|---|---|---|
| 资源 | 14 项矿物的数量 | 存档 `OwnedResources` + 名字表（M4 已建，14/14 核对过） | — |
| 角色 | 5 个槽、哪些有进度、每槽 XP/等级/晋升次数 | 存档 `CharacterSaves` + 升级曲线 | **角色名读不出来**（`CharacterClass` 全 None，存档里没有「哪槽是谁」） |
| KPI | 已完成/未完成的 KPI 项 | 存档 `UnLockedMissionParameters` 一类 | 需要 KPI 对照表 |
| 里程碑 | 54 项、各项当前等级 | 存档 `Milestones` | 需要里程碑对照表 |
| 战绩 | 总时长、局数、金币 | 存档 | — |

> 角色名读不出来这件事**已在 v0.2.0 定案**：不猜、不编，如实写「这一版分不出哪个槽是哪个职业」，等后续版本从别处找线索。

### 3.2 装备定制（v0.2.2 + v0.2.3）

用户要求尽量还原游戏内的定制界面。拆两版，因为**改装树本身就是一张大结构表**。

| 项 | 内容 | 版本 |
|---|---|---|
| 配装 | 4 职业，每职业 6 套配装，每套含主武器/副武器/工具等栏位的当前选择 | v0.2.2 |
| 武器改装树 | 每把武器 5 个改装位，每位的选项、当前选择、已解锁哪些 | v0.2.2 |
| 模组 | 已购模组 124 个、哪些已锻造/未锻造 | v0.2.3 |
| 皮肤 | 已解锁数量、哪几件、稀有度 | v0.2.3 |
| 十字镐 | 镐头/镐刃等部件的拥有与选择 | v0.2.3 |
| 喷漆图案 | 已解锁图案 | v0.2.3 |

**「已解锁 / 未解锁」的展示规则**（用户原话落成的条款）：

- 已解锁的改装：显示**效果**；
- 未解锁的改装：显示**效果 + 解锁需要消耗什么**（要资源就写资源与数量）；
- 不能只写「未解锁」三个字就算完。

### 3.3 天赋（v0.2.4）

| 项 | 内容 |
|---|---|
| 已购天赋 | 21 个，逐个显示效果 |
| 剩余星星 | **已领取里程碑奖励总数 − 已购天赋花费总和** |
| 里程碑解锁表 | 哪个里程碑给几点、共几级 |
| 未购天赋 | 显示效果 + 需要几点星星 + 前置 tier 条件 |

>Tier 规则：买够前一级 N 个才开下一级；额外被动槽在 Tier 4 / Tier 9 可买（wiki 两处写法不一致，实施时以游戏内实测为准）。

### 3.4 赛季 · 深潜 · 战役（v0.2.5，合成一页）

三块合起来只够撑一屏，所以合成一个「赛季与战役」页，每块一个区块。

| 块 | 能拿到 | 缺什么 | 怎么写 |
|---|---|---|---|
| 深潜 | 是否完成过、当前进度 | 每期深潜的具体内容 | 写完成过几次，不编「本周深潜是什么」 |
| 赛季 | 两个赛季各自的挑战发放时间 | 等级、链路图、当前选了哪条 | 按「挑战最后发放时间」推断当前赛季，并写明是**推断** |
| 战役 | 已解锁任务、星球区域、任务参数 | 任务清单与顺序 | 列已解锁项，不排顺序 |

> 这三块共同的原则：**能显示多少就显示多少，缺什么就写缺什么**，不为了页面好看去补游戏里根本没有的东西。

### 3.5 商店 · 酒吧（v0.2.6）

| 项 | 来源 | 备注 |
|---|---|---|
| 本体价格 / 折扣 | Steam `appdetails`（无需 key） | 实测：原价 ¥108，折后 ¥32.40，-70% |
| 各 DLC 价格 | 同上，逐个查 | 已知 DLC 列表在 `appdetails` 返回里 |
| 当前在线人数 | `ISteamUserStats/GetNumberOfCurrentPlayers`（无需 key） | 实测 8,972 人 |
| 月度峰值 | **不做** | SteamDB `/charts/` 实测 403 + ToS 禁爬；界面放链接让用户自己点 |
| 啤酒配方 | 公开 wiki 结构表 | 需要核对酒精含量与材料 |

### 3.6 Steam 社交（v0.2.7，垫底）

| 项 | 内容 | 前置 |
|---|---|---|
| 好友拥有这游戏 | 好友列表里有多少人玩 DRG | 用户自填 Steam Web API key |
| 成就进度 | 已解锁 / 总数、逐个成就 | 同上，且需公开个人资料 |

> **无 key 时整块隐藏**，不留空区块。key 存本地，和 mod.io 令牌同一套加密存储。

3. 版本发布前跑回归，且新增能力要有断言。

## §6 明确不做（写进路线图，防止以后反复讨论）

| 不做 | 理由 |
|---|---|
| 写存档 / 改档 | 只读是这条线的底线，一旦能写就会被当成作弊工具 |
| 月度峰值 | SteamDB 403 + ToS 禁爬；放链接代替 |
| 每局历史（采集 mod） | 依赖「游戏每局结束往日志写东西」，该前提未验证；**路线图留一行不编号** |
| 跨存档对比 / 排行榜 | 涉及上传玩家数据，超出"只读本地"的定位 |
| Bosco 定制 | **待核实**：存档顶层无 `bosco/drone/companion` 字段；且「七套配装」是玩家装备系统的结构，无人机大概率只有外观 |
