## §1 现状（动手前的事实，全部已核实）

### 1.1 布局：窗口拉大后右侧是死的

- 外壳 `app/src/styles.css:58-62`：`grid-template-columns: 160px 1fr` —— 内容区吃掉全部剩余宽度
- 但每个内容块自己卡了上限，且**没有 `margin: auto`**，所以是左对齐：

| 位置 | 选择器 | 上限 |
|---|---|---|
| `:144` | 状态卡 | 720px |
| `:212` | 搜索行 | 720px |
| `:220` | `.list` | 780px |
| `:318` | 卡片 | 720px |
| `:396` | `.vlist` 虚拟列表 | 780px |
| `:814` | 卡片 | 720px |
| `:832` | 行内说明 | 780px |
| `:940` | `.today-block` | 760px |

结果：1600px 窗口下内容只占左边约 780px，右边约 660px 是空的。

### 1.2 抽屉

- `.preview` 固定 `width: 360px`（约 `:1055`），`position: fixed; right: 0`
- `@media (min-width: 1000px) { section.with-preview { padding-right: 372px } }`（`:1063-1067`）—— 372 是 360+12 写死的

### 1.3 导航缺陷（P0）

- `app/src/components/settings/TokenCard.tsx:82`：`<a href={ACCESS_PAGE}>{ACCESS_PAGE}</a>`
- `app/src/components/settings/Ue4ssCard.tsx:174`：`<a href={status?.url ?? ""} target="_blank" rel="noreferrer">`
- `app/src-tauri/src/` 里 grep `on_navigation` / `will_navigate` **零命中**
- 后果：点这两处任意一个，WebView 自己导航过去，**整个应用界面被网页替换**，没有返回入口。用户实测过一次，表现为「白屏、不知道在加载还是卡死、回不去」
- 已有能力：`app/src-tauri/src/ipc/settings.rs:304` `open_url`，只放行 http/https，走系统浏览器。**缺陷不在它，在于那两处 `<a>` 根本没调它**

### 1.4 既有的规范面

- 20 个设计 token 已就位（8 个品牌色 + 间距/圆角/字号）
- 仍有约 16 处硬编码颜色未收进 token
- 三态（骨架 / 空 / 错）在「今天」页已做齐，其它页只做到「错」，空态多数**没有动作**

## §2 里程碑

### M8-1 导航缺陷（P0，先做）

1. **根治**：主窗口加导航拦截。除应用自身页面外，任何 URL 一律 `deny`，转调 `open_url` 交给系统浏览器。以后任何漏网的 `<a>` 都带不走应用。
2. **治标**：上面两处 `<a>` 换成按钮，点击走 `open_url`。
3. **反馈**：点击后**立刻**在本地把按钮变成「正在打开浏览器…」，并在底部出一条**一行轻提示**（如「已在浏览器打开」），2 秒自消。
4. 回归：新增场景覆盖「点令牌链接不改变主窗口 URL」「点 UE4SS 链接同理」「提示出现并在 2 秒后消失」。

**验收**：点任一链接 → 应用界面不动、系统浏览器打开目标页、底部有提示；连点三次不出现白屏。

### M8-2 布局适配（不做页面重排，只改宽度分配）

1. **列表页**（矿脉、背包、今天）：去掉内容块的固定上限，列表铺满可用宽度；多出来的宽度给「名字 + 简介」列，下载量与按钮固定右对齐。
2. **表单页**（设置、关于）：保持限宽但**居中**（`margin-inline: auto`），上限取 860px 左右。
3. **抽屉**：`width: clamp(320px, 32vw, 520px)`；`with-preview` 的 `padding-right` 改为跟着算（CSS 变量或 `calc`），不许再写死 372。
4. 断点复核：1100 / 1400 / 1700 / 1920 四档截图，确认没有横向滚动条、没有列挤压。

**验收**：1600px 窗口下右侧不留死白；列表能多看到简介列；设置页内容居中；四档截图无异常。

### M8-3 界面规范与人化（不动结构，只统一与补齐）

1. **规范收敛**：卡片、按钮、提示、表格行统一引用 token；把剩余约 16 处硬编码颜色收进 token（值不变，只换引用）。
2. **空态带动作**：每个空态给一个「下一步该干什么」的按钮或链接（如背包空 → 「去矿脉找一个」）。
3. **错误态可操作**：错误提示必须给动作（重试 / 打开设置 / 复制诊断），不许只显示一句话。
4. **三态一致**：骨架 → 内容 / 空 / 错，三页统一，不许有页面跳到「转圈」。
5. **无障碍基础档**：焦点可见（已有 2px 琥珀环，复用到新增控件）、Tab 顺序合理、Esc 可关抽屉与弹层、正文对比度不低于 4.5:1。

**验收**：三页各自走一遍「空 / 错 / 满」三种状态；键盘只用 Tab+Enter+Esc 能完成「搜 → 开抽屉 → 装 → 关」；对比度抽查通过。

### M8-4 治理与文档（这一版叫「定型」的理由）

1. `README.md` 增「治理」一节：怎么提 issue、怎么贡献、安全问题怎么报、名字与图标的使用边界。
2. `LICENSE` 顶部补版权行（`Copyright (c) 2026 Yisun229`），不改 GPL-3.0 正文。
3. **解耦 `productName`**：现在有约 9 行硬编码依赖它，改为从一处常量取，改名时不再牵一发动全身。
4. 文档化两条规则：**数据目录的三级回落**（env → exe 旁 → LOCALAPPDATA）、**版本号规则**（0.1.x 数「玩家能感觉到」的版本，y 级留给纯修 bug 的热修）。
5. 路线图 §2「实际」列回填到 v0.1.8。

**验收**：新人只看 README 就知道怎么参与、怎么报问题上、名字能不能用；改 `productName` 只改一处。

### M8-5 遗留收口

1. **③ 中国区说明**：把「mod.io 官方在中国大陆不可直连，需要自备网络条件」写进 README 与设置页的令牌卡片说明，措辞不要撇清、要直说。

**验收**：文档里搜「中国」能找到这句话，设置页令牌卡片下方也能看到。

> **① 干净 Windows 装机验证已移出本版**，排进 v0.1.8.1，见 §8。

### M8-6 回归与发布

1. 版本号统一 `0.1.8`（package.json / tauri.conf.json / Cargo.toml 三处）。
2. 全量回归（默认组 + 在线组单独探针）+ 单测。
3. 出安装包与便携包，算 sha256，三个附件齐。
4. 发布说明写「这一版定型了什么」，含已知限制。

**验收**：回归全绿；两个包能装能跑；release 三附件 digest 与本地一致。

## §3 边界（越界即视为未完成）

- **不改** 25+ 个命令的签名
- **不改** 数据目录结构（`data\` 下的三个子目录不动）
- **不换** 配色与字体
- **不重做** 页面结构（导航仍是那四页，信息仍是那些字段）
- **不引入** 新的 UI 组件库或动画库
- 提交一律用显式路径，不许 `git add -A`

## §6 风险

| 风险 | 应对 |
|---|---|
| 导航拦截写错，把应用自己的页面也拦了 | 白名单必须包含 tauri 协议与 dev 的 localhost；先用回归场景验「切页不受影响」 |

| 干净机器验证需要第二台机器 | 用全新 Windows 用户配置（新建本地账户）等效替代，并在记录里写明 |

## §8 顺延到 v0.1.8.1（不在本版）

| 项目 | 为什么顺延 | 验收 |
|---|---|---|
| ① 干净 Windows 装机验证 | 用户有第二台机器，把「真机首装」这件事做实，排到 v0.1.8.1 | 在真实第二台机器上走完「装 → 开 → 装一个 mod → 卸 → 查残留」；记录逐条打勾；发现的问题在 v0.1.8.1 修掉 |

**v0.1.8 的发布说明必须如实写**：本版**未**在第二台干净机器上做安装验证，该项排在 v0.1.8.1。不要含糊，也不要写成「已验证」。

**v0.1.8.1 的定位**：y 级补丁版，按版本号规则只承载「真机验证发现的问题 + 必要的修复」，不夹带新功能。

**一个风险要说清楚**：把「发布前验证」改成「发布后验证」，等于让第一个真实用户承担首装风险——目前那个用户就是你。如果那台机器在本版发布前就能用，建议提前做，因为它在那个环节发现的问题，本来就该属于 v0.1.8。
