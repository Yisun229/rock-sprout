## §3 里程碑拆解

### M0 · 修 Guid 读取 bug（P0，先于一切）

**现象**：Rust 输出的 `SavegameID`、`KPIGuid`、`PerkID`、`WeaponID`、配装里的武器 GUID **全部是 0**；同一份存档用 JS 解析出来的却是真值。

**根因**（已定位）：
- `app/src-tauri/src/save/model.rs:311-316` `as_guid` 只匹配 `Value::Binary`
- 但 `app/src-tauri/src/save/gvas.rs:555-568` 对裸结构体返回的是 `Value::Struct { props: [Property { name: "$binary", value: Value::Binary(..) }] }`

**修法**：`as_guid` 增加对 `Value::Struct` + 单字段 `$binary` 的识别（或在 `structured()` 处直接把 16 字节判成 Guid）。**二选一，改一处，不要两处都改**。

**验收**：
1. 主档 `SavegameID` 解析出非 0，且与 JS 参考实现（`_tools/_gvas.mjs`）逐字节一致
2. 54 条 `KPIGuid` 不再全 0（`_tools/_m2-first.json` 里 54 条 unique=1 即此 bug 的物证）
3. 补单测：裸 Guid 结构体、数组元素内的 Guid、map 键的 Guid 三种位置各一条

> 这个 bug 不影响 v0.2.0 用户看到的画面（那版只显示数字和资源名），但**v0.2.1 之后每一步都建立在 GUID 上**，所以必须第一个修。

### M1 · 结构表（单独提交、单独验收）

| 表 | 内容 | 来源 | 验收 |
|---|---|---|---|
| `levels.json` | XP → 等级曲线 | 社区 wiki + 游戏内实测抽查 | 三个真实槽（XP 7047 / 8121 / 315000）反算等级与游戏内一致；315000 是否为满级阈值要明确回答 |
| `milestones.json` | **并集 56 条**的 `KPIGuid` → 名称 | 官方 wiki 全表 | 主档的 54 条全部能对上；缺的显示 `#id` |
| `milestone-tiers.json` | `Tier`(1–5) 的含义与对应点数 | 官方 wiki | **说清 Tier 是「里程碑等级」还是「奖励点数」；查不清就停下来问，不许猜** |

> 每张表都要写 `$source` / `$verify`，格式照 `names.json`。

### M2 · 后端聚合

1. 新增命令 `my_dwarf_view`（**不改** v0.2.0 已有四个命令的签名）
2. 等级计算：读 `levels.json`；曲线缺失或对不上时该字段返回 `null`，前端退回 XP
3. 角色块数据：`XP` + `TimesRetired` + `RetiredCharacterLevels`，三个都已在 Rust 侧落字段
4. 里程碑：把 `ClaimedKPIRewards` 按 `KPIGuid` 查表起名，查不到返回 `#id`
5. **不许**在 Rust 里写死任何名字或数值

### M3 · 前端

- 资源块：14 行两列（现有资源卡已具名渲染前 4 条，扩到全部 14 条并去掉「另有 N 项」截断）
- 角色块：5 行，每行「角色 N」+ 等级（或 XP）+ 晋升次数 + 退休等级
- 里程碑块：折叠，摘要「已领取 N 条」，展开列出条目
- 汇总行：保留

**空态与错误态**：
