## §1 范围

### 做

1. **资源块**：14 项矿物名称 + 数量（名字表已有，`app/src/data/names.json` 的 `resources` 14 条）

- 不显示「还差什么里程碑」——存档不记进度，做不到
- 不做里程碑图标、资源图标
- 不做角色立绘/头像
- 不碰 v0.2.2 的装备定制
- 不做多存档对比

## §3 里程碑拆解

### M1 · 结构表（最大变数，单独交）

三张表，全部落到 `app/src/data/`，与 `names.json` 同目录、同格式（带 `$source` / `$verify` 声明）：

| 表 | 内容 | 来源 | 验收 |
|---|---|---|---|
| `levels.json` | XP → 等级曲线（1–25 级 + 晋升后循环） | 社区 wiki + 游戏内实测抽查 | 用三个真实槽的 XP 反算等级，与游戏内截图一致 |
| `milestones.json` | 54 条里程碑的 GUID → 名称 | 官方 wiki 全表 | 54 条全部有名字，缺的标 `#id` 并写清缺失 |
| `milestone-tiers.json` | `Tier` 字段的含义与对应点数 | 官方 wiki | 先说清 Tier 到底是「里程碑等级」还是「奖励点数」——**查不清就停，回来问** |

> **M1 单独提交、单独验收**。表没建完，M2 不许开工——这版的坑全在表上，不在代码上。

### M2 · 后端聚合

1. 在 `ipc/save.rs` 里把已解析的七块聚合成「我的矿工」视图，新增命令 `my_dwarf_view`（**不改动** v0.2.0 已有的命令签名）
2. 等级计算：读 `levels.json` 算，曲线缺失或对不上时该字段返回 `null`，让前端退回 XP
3. 职业反推：拿该角色 `Loadouts` / `ItemUpgradeLoadouts` 里的武器 GUID，去 `names.json` 的 `overclocks`/武器表里找归属职业；推不出返回 `null`
4. **不许**在 Rust 里写死任何名字或数值

### M3 · 前端四块

沿用现有样式 token，不加新颜色：

- 资源块：14 行，两列（名称 / 数量），数量右对齐
- 角色块：5 行，每行「职业名或角色 N」+ 等级 + 晋升次数 + 退休等级
- 里程碑块：`<details>` 风格折叠，摘要「已领取 54 条」，展开后 54 行
- 汇总行：保留 v0.2.0 的四个数字

**空态与错误态**（沿用 v0.1.8 立的规矩）：

| 情况 | 显示 |
|---|---|
| 找不到存档 | 沿用 v0.2.0 的三态文案，不重复造 |
| 某槽 `XP = 0` 且 `TimesRetired = 0` | 「这个槽还没进度」 |
| 等级算不出 | 该行显示 XP 原值 + 一行小字「等级暂时算不出」 |
| 职业推不出 | 显示「角色 N」 |
| 里程碑名称缺 | 显示 `#<id 前 8 位>` + 一行「这个名字还没对上」 |

### M4 · 回归与证据

1. 新增回归场景（`_tools/check-all.mjs`）：三块都出现、折叠能展开、缺名字时显示 `#id`、等级缺失时退回 XP
2. 三种存档状态各截一张图（正常 / 无存档 / 字段缺失）
3. 单测至少覆盖：等级曲线边界（0 XP、刚好满级、超出曲线）、职业反推的命中与未命中

### M5 · 出包

版本号 0.2.1（四处：`package.json`、`tauri.conf.json`、`Cargo.toml`、`Cargo.lock`）、安装包 + 便携包、SHA256SUMS、发布说明。

## §5 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 升级曲线核对不上 | 等级显示错 | 退到显示 XP（决策 4），并在发布说明写明 |
| 里程碑 Tier 含义不清 | 无法算星星 | **停下来问**，不猜；v0.2.4 的天赋依赖它 |
| 武器→职业表缺失 | 职业反推全失败 | 全部退回「角色 N」，不影响其他块 |
| 结构表拖时间 | 超过 4 天 | M1 单独交，M2–M5 在其后；宁可晚一天，不带着错表发布 |
