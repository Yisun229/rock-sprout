# 岩笋 · Rock Sprout — v0.1.4 实施计划

> **依据**：`文档\路线图-v0.1到v1.0.md` §4「v0.1.4 好看」
> **这一版的目标**：视觉打磨到位——最终图标、动效、主题收尾
> **一句话目标**：让人第一眼看得出这是个正经产品，不是脚本套了个壳
> **前置状态**：v0.1.3 已发布；31 个命令；前端 3,558 行 / 单 `styles.css` 625 行；**当前全项目零动效**；图标仍是 Tauri 脚手架默认件
> **量级**：小 · 实际预计 4 个工作日

---

## 0. 决策清单

### 0.1 已定

| # | 决定 | 出处 |
|---|---|---|
| 1 | 本版**只做视觉**，不新增页面、不新增命令 | 路线图 §4 |
| 2 | **布局不动**（rail 宽度、栅格、卡片结构一律保持 v0.1.3 原样） | 计划侧定，可推翻 |
| 3 | 动效用**纯 CSS**，不引动画库 | 计划侧定，可推翻 |
| 4 | **只做暗色**，不做亮色主题切换 | 计划侧定，可推翻 |
| 5 | 图标本版**定稿**，产出 ico + 全套 png | 路线图 §4「最终图标」 |
| 6 | 不引入 UI 组件库、字体文件、图标库 | 承接 v0.1.0 的零依赖决定 |
| 7 | 31 个命令的签名与数据结构**零改动** | 全程边界 |

### 0.2 「想打开」这条宗旨在本版的位置

路线图 §1 新增的第一判据是「想打开」。它不是一个功能，是一把尺子。本版只承担其中一半：

- **v0.1.4 负责**「打开之后不失望」——这是视觉打磨能直接兑现的部分；
- **v0.1.5 负责**「就算不玩也想打开」——那需要一块每天会变的内容（每日一页），属于新功能，不在本版。

这一条写在这里，是为了让执行方知道：**本版不要为了"想让人打开"去加任何新东西**，那是下一版的事。

### 1.2 缺的

| 缺什么 | 证据 | 影响 |
|---|---|---|
| **零动效** | `grep transition\|@keyframes\|prefers-reduced-motion` 在 `src/` 下**零命中** | 切换、加载、操作全无反馈，像静态网页 |
| **图标是脚手架默认件** | `src-tauri/icons/` 全部文件时间戳都是 10-28 01:16，与 Tauri 模板一致 | 任务栏、开始菜单、安装器里是我们不认识的样子 |

| **三态不统一** | 空列表、加载中、出错三种状态在各页面各写一套，`ErrorHint.tsx` 只管错误 | 同一种"没东西"长得不一样 |

### M4-1 · token 补齐（0.5 天）

**做什么**
- 在 `src/styles.css:2-11` 的 `:root` 里追加：
  - 间距：`--sp-1..--sp-6`（4 / 8 / 12 / 16 / 24 / 32 px）
  - 圆角：`--r-sm 2px`、`--r-md 3px`、`--r-lg 4px`（**保持尖角调性，最大 4px**）
  - 字号：`--fs-sm 12px`、`--fs-md 14px`、`--fs-lg 18px`、`--fs-xl 22px`
  - 动效：`--dur-fast 120ms`、`--dur-base 180ms`、`--ease-out cubic-bezier(0.2, 0, 0, 1)`
- 把 625 行里散落的同类硬编码值改成引用变量

**不要做的**：不要顺手改任何一处视觉结果。这一阶段的目标是**重构零视觉变化**——改完截图应该和基线逐像素接近。

**验收**：`git diff` 只增加变量与引用替换；三张截图与基线无明显差异。

### M4-2 · 图标定稿（1 天）

**做什么**
- 出一份 `assets\icon.svg`：方形画布，岩笋形态（尖顶、哑光、矿琥珀主色 + 岩底背景），要求缩小到 32px 仍能辨认
- 用 Tauri 自带命令生成全套：`cargo tauri icon assets\icon.svg`，产出会覆盖 `src-tauri/icons/` 下的 `32x32.png`、`64x64.png`、`128x128.png`、`128x128@2x.png`、`icon.ico`、`icon.icns`
- 核对 `tauri.conf.json:34-39` 的四个路径全部存在且非空
- 新增关于页，显示大图标 + 版本号 + 仓库链接 + GPL-3.0 一行

**为什么**：图标是"第一眼正经产品"最便宜的一笔投入——它出现在任务栏、开始菜单、安装向导、文件属性四个地方。

**验收**：任务栏 / 开始菜单 / 安装器 / 关于页四处图标一致；32px 下能认出是岩笋。

---

### M4-3 · 动效（0.5 天）

**做什么**——只做三类，别做第四类：

1. **切页**：内容区淡入 + 上移 4px，`--dur-base`；三个页面都靠 `appStore.tsx` 的 `visited` 保持挂载，所以做的是"显示类名的切换"，不做重挂载
2. **列表项出现**：搜索结果首次渲染时，逐项 `opacity 0→1`，每项延迟最多 12ms（封顶 120ms，避免长列表排队太久）
3. **操作反馈**：按钮 `:active` 缩放 0.98、队列条进度宽度过渡、`ConflictBadge` 出现时轻微放大

**必须有**：`@media (prefers-reduced-motion: reduce)` 里把上述全部动效时长归零。

**验收**：开启 Windows「减少动画」后，界面无任何过渡动画；正常模式下切页与列表出现可见但不拖沓。

---

### M4-4 · 三态补齐（1 天）

**做什么**
- 新建三个组件，放在 `src/components/states/`：
  - `EmptyState`：一个图标位 + 一句主文案 + 一句说明 + 可选一个按钮
  - `LoadingState`：骨架块（3~5 行），不做转圈
  - `ErrorState`：错误文案 + 一个"重试"按钮，替代 `ErrorHint.tsx` 在页面级的使用
- 替换点：
  - 矿脉：搜索无结果、搜索中、搜索失败
  - 背包：未安装任何 mod、读取失败
  - 设置：令牌未填、配置读取失败
- `ErrorHint.tsx` 保留，降级为"行内小提示"，不再承担整页错误

**为什么**：用户第一次打开时看到的多半是空状态和加载状态，而不是满载列表。三态不统一，等于第一印象靠运气。

**验收**：三页面在"空 / 载入中 / 失败"三种情况下，视觉风格一致。

**验收**：键盘 Tab 走完一页不丢失焦点位置；鼠标悬停与选中一眼能分清。

## 4. 验收标准

- [ ] 三页截图与 `before` 明显不同，且不像换了个软件（配色与形态不变）
- [ ] 任务栏 / 开始菜单 / 安装器 / 关于页四处图标一致
- [ ] 开启「减少动画」后无任何过渡动画
- [ ] 三页面的空 / 载入 / 失败三态统一
- [ ] 键盘 Tab 全程有可见焦点
- [ ] `check-all.mjs` 70 场景全过
- [ ] 安装包 < 10 MiB、冷启动 < 1.5 秒（v0.1.3 基线 4.33 MiB / 329 ms）
- [ ] 31 个命令签名未变（`git diff` 里 `src-tauri/src/ipc/` 无改动）
- [ ] `CHANGELOG.md` 有 v0.1.4 条目

## 5. 明确不做

- 亮色主题、主题切换器
- 布局重做（侧栏宽度、栅格、卡片结构）
- 动画库（framer-motion 之类）
- 字体文件（中文子集太大，继续用系统字体栈）
- 新页面、新命令、新数据
- 多语言（继续中文硬编码在 `src/locales/zh-CN.ts`）
- 「每日一页」——那是 v0.1.5

## 7. 风险

| 风险 | 应对 |
|---|---|
| 图标美术出不来（这是唯一依赖"画"的一步） | 计划侧先出 SVG 草稿，执行方只做生成与替换；草稿不合格不阻塞其它阶段，图标可后补 |
| 动效在 WebView2 上掉帧 | 只用 `transform` 与 `opacity`，不碰 `width/height/top/left`；列表项动画封顶 120ms |
| token 重构引入视觉回归 | M4-1 要求"零视觉变化"，截图对比不过就回退该阶段 |
| 三态替换漏改导致重复渲染 | 替换时逐页做，每改完一页跑一次 70 场景 |
| 图标生成覆盖掉现有文件 | 先在 `_tools\attic\icons-before-0.1.4\` 备份整个 `src-tauri\icons\` |
