# 岩笋 · Rock Sprout — v0.1.4 实施计划

> **依据**：`文档\路线图-v0.1到v1.0.md` §4「v0.1.4 好看」
> **这一版的目标**：视觉打磨到位——最终图标、动效、主题收尾
> **一句话目标**：让人第一眼看得出这是个正经产品，不是脚本套了个壳
> **前置状态**：v0.1.3 已发布；31 个命令；前端 3,558 行 / 单 `styles.css` 625 行；**当前全项目零动效**；图标仍是 Tauri 脚手架默认件
> **量级**：小 · 实际预计 4 个工作日

---

## 0. 决策清单

### 0.1 已定

| # | 决定 | 出处 |
|---|---|---|
| 1 | 本版**只做视觉**，不新增页面、不新增命令 | 路线图 §4 |
| 2 | **布局不动**（rail 宽度、栅格、卡片结构一律保持 v0.1.3 原样） | 计划侧定，可推翻 |
| 3 | 动效用**纯 CSS**，不引动画库 | 计划侧定，可推翻 |
| 4 | **只做暗色**，不做亮色主题切换 | 计划侧定，可推翻 |
| 5 | 图标本版**定稿**，产出 ico + 全套 png | 路线图 §4「最终图标」 |
| 6 | 不引入 UI 组件库、字体文件、图标库 | 承接 v0.1.0 的零依赖决定 |
| 7 | 31 个命令的签名与数据结构**零改动** | 全程边界 |

### 0.2 「想打开」这条宗旨在本版的位置

路线图 §1 新增的第一判据是「想打开」。它不是一个功能，是一把尺子。本版只承担其中一半：

- **v0.1.4 负责**「打开之后不失望」——这是视觉打磨能直接兑现的部分；
- **v0.1.5 负责**「就算不玩也想打开」——那需要一块每天会变的内容（每日一页），属于新功能，不在本版。

这一条写在这里，是为了让执行方知道：**本版不要为了"想让人打开"去加任何新东西**，那是下一版的事。

### M4-3 · 动效（0.5 天）——✅ 已完成 `7ab1970`

**实测结果（2026-10-29）**

| 项 | 改造前 | 改造后 |
|---|---|---|
| 切页淡入（背包） | 无动画 | 32 帧落在 0~1 之间，透明度 0.01→1 |
| 列表项错峰 | 无 | 第 1/4/10 条延迟 0 / 0.036 / 0.108 秒 |
| 错峰封顶 | — | 第 13、41 条都是 0.12 秒（封顶生效） |
| 减少动画（切页） | — | 渐变帧 0 个，动画名 none |
| 减少动画（按钮） | — | 过渡 none / 0s |
| 回归 | 70 | **71 / 71** |
| 冷启动 | 329 ms | 344 ms（+15 ms，噪声级） |
| 空闲内存 | 355 / 363 MB | 355 / 362 MB（持平） |
| 1000 条滚动 | 5.6 ms/帧 | 5.6 ms/帧（不变） |

**踩到的坑（值得记住）**：`animation-fill-mode` 一开始写成 `both`，动画结束后每行永久留在合成层上，文字抗锯齿从次像素渲染退化成灰阶——肉眼只是"有点糊"，**像素比对却能抓出 1670 个点不一样**。改成 `backwards` 后立刻回到 106 像素（只剩时间戳）。**不要用 `both` / `forwards`，会永久提层。**

**待复测**：装一个 mod 从 783 ms 变成 930 / 1102 ms，两次自差 170 ms，判断是机器负载。**要在安静环境重测**；若仍偏高，先查 `QueueBar.tsx` 的进度更新频率是不是每个 chunk 都 setState（应节流到 ~100 ms 一次），而不是先怀疑动画。

**做什么**——只做三类，别做第四类：

1. **切页**：内容区淡入 + 上移 4px，`--dur-base`；三个页面都靠 `appStore.tsx` 的 `visited` 保持挂载，所以做的是"显示类名的切换"，不做重挂载
2. **列表项出现**：搜索结果首次渲染时，逐项 `opacity 0→1`，每项延迟最多 12ms（封顶 120ms，避免长列表排队太久）
3. **操作反馈**：按钮 `:active` 缩放 0.98、队列条进度宽度过渡、`ConflictBadge` 出现时轻微放大

**必须有**：`@media (prefers-reduced-motion: reduce)` 里把上述全部动效时长归零。

**验收**：开启 Windows「减少动画」后，界面无任何过渡动画；正常模式下切页与列表出现可见但不拖沓。

### 10.3 一条实现约束（改的是 M4-3 的做法）

三个页面靠 **`hidden` 属性**保持挂载（`App.tsx:75-83`）。`hidden` 等价于 `display:none`，而**元素在 `display:none` 下不执行 transition**。所以切页动效不能写成"给元素加 transition"，只能写成：切页时给页面容器加一个 `anim-in` 类触发 `@keyframes`，动画结束摘掉类。**不改 reducer，不改挂载策略。**
