## 3. 里程碑详解

### V2-M0 记账修正（3 天）

**要解决**：同一个 mod 从两个路径导入，算成两个 id，列表里出现两条。

**改哪**

1. `app\src-tauri\src\local.rs` — `id_for(path: &str) -> u64`（约第 30 行）
   - 改成先 `std::fs::canonicalize` 再哈希。
   - **Windows 注意**：`canonicalize` 会返回 `\\?\E:\...` 前缀，哈希前必须剥掉，否则同一文件两种结果。
   - 大小写：Windows 路径不区分大小写，哈希前统一转小写。

2. `app\src-tauri\src\config.rs` — 加迁移函数 `migrate_local_ids()`
   - 启动时跑一次：遍历 `installed` 记录，用新算法重算 id。
   - 重算后若与已有记录撞了 → 合并成一条，保留更早的 `installed_at`。
   - 文件不存在 → **不删除**，标 `missing: true` 保留在列表里，界面上灰显并提供「仅删记录」按钮。

3. 新增 `app\src-tauri\src\ipc\maintenance.rs` — `delete_record_only(id)` 命令，供"仅删记录"用。

**怎么验**

- 把同一个 mod 文件夹复制到两个路径，分别导入 → 背包里只有一条，且指向先导入的那份。
- 拿一份 v0.1 的旧配置（含已删除文件）启动 → 所有记录还在，缺文件的灰显，点"仅删记录"能消掉。
- 迁移跑两次结果一致（幂等）。

### V2-M1 状态层（4 天）

**只做支撑批量必需的部分，不做全面组件化。**

**改哪**

1. `app\src\App.tsx`（约 52–56 行）— 现在是条件渲染，切页即卸载
   - 改成三个页面**都挂载**，用 `hidden` / `display:none` 控制显示。
   - 目的：切回来时列表、滚动位置、勾选都还在。

2. 新增 `app\src\state\selection.ts` — 选中态（React context + reducer）
   - 存 `Set<string>`（mod id），矿脉和背包共用一份。
   - 提供 `toggle` / `toggleAll(ids)` / `clear` / `has`。
   - **只存 id，不存整条数据**——数据可能因刷新而变。

3. 新增 `app\src\state\queue.ts` — 任务队列的纯数据部分（真正跑的任务在 M3 接）
   - 结构：`{ id, kind: 'install' | 'uninstall', state: 'pending' | 'running' | 'done' | 'failed', error? }`
   - 本阶段只做结构和 reducer，不接后端。

4. `app\src\main.tsx` — 开发模式下 StrictMode 会双发请求，用一次性标记包住初始加载，避免进入 v0.2 后看起来像"队列跑了两遍"。

**怎么验**

- 矿脉勾 3 个 → 切背包 → 切回：3 个还是勾着的，列表没重新加载。
- 页内滚动到中间 → 切走 → 切回：滚动位置不变。
- 三页来回切 10 次，网络面板里请求数不增加。

### V2-M2 检测接线（5 天）

**这是本版最大的坑**：检查器写好了，但从来没通过电。

**改哪**

1. `app\src-tauri\Cargo.toml` — `indexmap` 打开 `serde` 特性（约第 43 行）
2. `app\src-tauri\src\mod_lints\mod.rs`
   - `LintReport` 与各 `Finding` 结构体加 `#[derive(Serialize)]`（约第 258 行）
   - **修多 pak 漏检**：约第 101 行 `individual_pak_readers.remove(0)` → 改成遍历全部 reader，逐个包检测后再合并结果
3. 新增 `app\src-tauri\src\cache\pakmanifest.rs` — 资源清单缓存
   - 路径：`<数据目录>\cache\pakmanifest\<sha256>.json`
   - 内容：该 pak 内所有资源的虚拟路径（排序后存，便于比对）
   - **按内容命名，永不失效**：文件内容不变，清单就不变；文件一变，哈希变，自然重算
   - 读取顺序：先算 sha256（**要按 64KB 分块边读边算**，别整个读进内存）→ 查缓存 → 没有就解包生成
4. 新增 `app\src-tauri\src\ipc\lint.rs` — 两个命令
   - `precheck_install(mod_ids: Vec<String>) -> LintReport`：问"假设装上这几个，会跟已装的撞哪些"
   - `scan_conflicts() -> LintReport`：问"现在已装的里面，谁盖了谁"
5. `app\src\api.ts` — 补齐两个命令的类型与调用封装

**怎么验**

- 装两个都改同一把武器的 mod → `scan_conflicts` 能报出这两个，并指出被覆盖的资源路径。
- 造一个含 3 个 pak 的 zip 导入 → 预检能发现第 2、3 个 pak 里的冲突（v0.1 只看第一个）。
- 装够 15 个 mod 后，第二次预检耗时 **< 300ms**（第一次慢没关系，缓存生效后要快）。
- 把某个已装 pak 手动改一个字节 → 预检会自动重算，不吃旧缓存。

**实测记录（已完成）**

实际落地跟计划的差别，说清楚免得下次对着计划找不到代码：

- 资源清单与比对逻辑集中在新文件 `app\src-tauri\src\manifest.rs`（约 470 行，含 6 个单测），没有另建 `cache/pakmanifest.rs`；缓存路径仍是 `<数据目录>\cache\pakmanifest\<sha256>.json`，**按 64KB 分块边读边算 sha256**（`const CHUNK: usize = 64 * 1024;`）。
- 两个命令放在已有的 `app\src-tauri\src\ipc\mods.rs`，没有另建 `ipc/lint.rs`：`precheck_install(mod_ids: Vec<String>)`（入参按计划从 `items` 改名成 `mod_ids`，每项可以是本地路径或已装记录的数字 id）与 `scan_conflicts()`。
- 检查器接线：`LintReport` 与 `SplitAssetPair` 已加 `Serialize`，`mod_lints/mod.rs` 里 `individual_pak_readers.remove(0)` 已改成遍历每个 pak（v0.1 只看第一个的漏检已修）；打不开的包不再无声跳过，改成记一条警告。
- 每个 mod 都会带的公共文件不算撞：`fsd/assetregistry.bin` 与 `fsd/content/_interop` 只记一条警告（合并时会重新拼，依据 `integrate.rs:442` 与 mint 自己的白名单）。

实测数字：`cargo test --lib` 52 个测试全过；同一个包预检第一次 20 处冲突 / 4 ms、第二次 2 ms（命中缓存）；换一个不撞的包 0 处 / 10 ms 并给一条公共文件警告。

### V2-M3 批量操作（5 天）

**并发策略（定死，别改）**

- **下载：2–3 路并发。** 再多会撞 mod.io 的限速，反而更慢。
- **pak 合并：严格串行。** 合并要读写同一个 pak 目录，并发会互相踩。
- **一个失败不影响其它。** 失败的进失败队列，可单独重试。

**改哪**

1. `app\src\state\queue.ts` — 接上真实任务：下载阶段并发，合并阶段串行，用 `await` 串成流水线
2. `app\src\pages\MineVein.tsx` — 加多选：每行复选框、全选、Shift 连选
3. `app\src\pages\Backpack.tsx` — 同上，且**卸载前必须弹确认框，列出将被删的 mod 名称和数量**
4. 新增 `app\src\components\TaskBar.tsx` — 底部常驻进度条
   - 只在有任务时出现；全部结束后保留，直到手动关闭
   - 显示：总数 / 已完成 / 失败数；失败项可展开看原因
5. `app\src-tauri\src\ipc\mods.rs` — 批量卸载走串行，单条失败继续下一条，最后一次性返回成功/失败清单

**怎么验**

- 一次勾 5 个装：底部条显示进度，其中 1 个故意给错地址 → 其余 4 个照常装完，失败的那个可重试。
- 一次勾 8 个卸：**先弹确认框列出 8 个名字**，确认后执行；中途关掉程序再开，已完成的不会回滚。
- 装的过程中切到别的页，进度条还在走。

**实测记录（已完成）**

- 队列在 `app/src/hooks/useQueue.ts`（下载 2 路并发 `CONCURRENCY = 2`、合并用一条 promise 链严格串行）；底部常驻进度条叫 `app/src/components/QueueBar.tsx`（计划里写的 `TaskBar.tsx`），收起明细、停在当前这个、只重试没成的都在。
- 后端为此拆了两个命令：`download_mod(id)`（只下载 + 记账）与 `apply_all()`（按记账重建合并包），单个 `install_mod` 原样保留，**没有改动任何既有命令的签名**。
- 多选：矿脉与背包共用同一份选中态（放全局 store），单击勾选、Shift 连选、Ctrl/Cmd+A 全选（输入框里不抢）、Esc 清空。
- **卸载前一定弹确认框**：`app/src/components/ConfirmDialog.tsx`，标题「真的要卸掉这 N 个？」，正文逐个列名字，确认后才进队列。
- 失败不整体回滚、可只重试失败项，都在队列里实现。

实测：断网（死端口代理）下勾 3 个一起装 → 3 条各自写明「连不上 mod.io…」，不留半截；批量卸 2 个 → 先弹确认框，确认后清空，界面显示「现在一个都没装」；制造一条失败（删掉它的记账）→ 1 成 1 败，成的不回滚。

### V2-M4 冲突界面（4 天）

**改哪**

1. `app\src\pages\Backpack.tsx` — 每行加状态徽章
   - `被覆盖`（灰） / `覆盖了 N 个`（琥珀） / `无冲突`（不显示，别占地方）
2. 新增 `app\src\components\ConflictDrawer.tsx` — 点徽章打开抽屉
   - 列出：谁覆盖了它 / 它覆盖了谁 / 重叠的资源路径
   - 一句话结论放最上面，路径列表收在下面
3. 背包顶部加「只看冲突」开关
4. 新增 `app\src\components\PrecheckDialog.tsx` — 装前汇总确认框
   - 一次装 5 个、其中 3 个有冲突 → **汇成一条**，不逐条弹
   - 写清"这 3 个会互相覆盖，最后生效的是 X"，给「仍然安装 / 取消」

**文案原则：写后果，不写术语。**
- 不写「资源路径冲突」，写「装了它，XXX 的武器伤害就不生效了」
- 不写「override」，写「盖住」

**怎么验**

- 装两个同改武器的 mod → 背包里后者显示「覆盖了 1 个」，点开能看到它是怎么盖的。
- 打开「只看冲突」→ 列表只剩有冲突的。
- 一次勾 5 个（3 个撞）→ 只弹一个框，读得懂会发生什么。

**实测记录（已完成）**

- 徽章：`app/src/components/ConflictBadge.tsx` 两个状态 —— 被别的包改过（灰，「被覆盖」）、改过别人的文件（琥珀，「盖了 N 处」），都没有就不渲染。
- 抽屉：`app/src/components/ConflictDrawer.tsx`，背包顶栏「看看谁盖了谁」打开，先给一句结论，再列谁盖了谁。
- 开关：背包顶栏「只看有冲突的」。
- 装前确认框：`app/src/components/PrecheckDialog.tsx`（套在通用 `ConfirmDialog` 上），一次装多个只弹一条，正文是预检摘要 + 前几条冲突路径 + 警告。
- **已知限制**：还没下载过的 mod.io mod，后端手里没有包，算不出它会撞谁 —— 这种情况直接进队列装，装完在背包里靠徽章看结果。本地文件与已经下过的包，预检是准的。

实测（离线）：把同一个包换成不同文件名与 id 造出「两边改同一批文件」→ 背包里一个显示「被覆盖」、一个显示「盖了 20 处」，抽屉能打开且说清谁盖谁，「只看有冲突的」打开后两行都还在。

## 5. 风险

| 风险 | 应对 |
|---|---|
| 冲突检测的误报会让人不敢用 | 只报**确定会覆盖**的；拿不准的降级成提示，不拦截 |
| 批量合并中途断电，pak 目录可能半成品 | 合并前把将被修改的文件先列出来，失败时提示"哪些可能不完整"；完整的快照留给 v0.3 |
| 迁移逻辑第一次跑，可能弄丢记账 | 迁移前把 `installed` 配置复制一份成 `.bak`，出问题能回退 |
| `canonicalize` 在 Windows 上的前缀与大小写问题 | M0 第一条就要单独测：同一文件三种写法（相对路径、绝对路径、带 `\\?\`）必须算出同一个 id |

## 6. 本版不做、但要留接口的

- **文案外置**：所有界面文案走一个常量文件，不散落在 JSX 里。为将来加英文留缝，本版不出英文。
- **游戏 id 常量**：`mod.io` 的游戏 id 只出现在一个常量里（`2475`），将来要支持别的游戏只改一处。
- **存档解析**：不碰。v1.1 才起地基。

## 8. 交付实况（v0.2 收尾后）

- 版本号 `0.2.0`，安装包 `RockSprout_0.2.0_x64-setup.exe`（6.65 MiB）+ `SHA256SUMS.txt`，已发到 <https://github.com/Yisun229/rock-sprout/releases/tag/v0.2.0>；tag `v0.2.0` 指向打这个包的那次提交 `42e7046`，发布后从 GitHub 下载回来重算 sha256 与本地一致。
- 回归脚本 `_tools\check-all.mjs` 当时的覆盖是 29 个场景；v0.3 开工时加了两条基线（装完不留 `.tmp`/`.prev`、记录原 pak 与合并包大小），现在跑是 31 个场景全过。
- 单元测试 52 个全过；`游戏目录` 每次跑完自动还原（合并包删掉、加载器换回游戏自带的）。
- 总验收第 7 条「陌生机器能装能跑」只核了 SHA256 这一段，干净机器实装还没人验。
