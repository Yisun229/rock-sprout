# v0.3.0 实施计划 · 模拟配装（只读）

> **依据**：`文档/路线图-v0.1到v1.0.md` §4「v0.3.0 模拟配装（只读）：解包武器基础数值与改装效果 → 逐属性显示 42 → 47.0」
> **一句话目标**：在武器抽屉里选出几条改装，立刻看到这把枪的伤害、弹匣、射速这些数变成多少——**不写存档、不算 DPS、不碰游戏目录**。
> **这一版有真实的失败可能**：数值抽不出来就退，M0 是先验关卡，不是走过场。

## §0 决策（十五项，全部已拍板）

| # | 决策 | 为什么 |
|---|---|---|
| 1 | 能**从已解锁的改装里试装**，实时看数值变化 | 只能看不能换不叫模拟；允许选未解锁的等于承诺一件游戏里做不到的事 |
| 2 | 显示**全部属性**，受影响的那些标出变化 | 只显示受影响的，会让人以为枪只有那几个属性 |
| 3 | 变化写成 `42 → 47.0` 并排 | 「原来多少」和「现在多少」是两件事 |
| 4 | 同属性：**百分比先相加→乘基础值→最后加固定值** | 常见模型，易解释 |
| 5 | 放在装备页的**武器抽屉**里，不新开页 | 抽屉本来就承载「这把枪的一切」 |
| 6 | **不做** A/B 配装对比 | 复杂度在「两套并存时谁是真身」，本版不碰 |
| 7 | 只做**六项核心属性**：伤害 / 弹匣容量 / 备弹 / 射速 / 装填时间 / 射程 | 194 个取值逐条定中文名是几天纯手工，玩家看的就是这几项 |
| 8 | 伤害取**直击组件**并注明来源，其他伤害组件折叠列出 | 伤害不能藏；但取哪个必须写清，玩家发现和面板对不上时能立刻定位 |
| 9 | 没有数值效果的改装照常显示，写「这条的效果在游戏逻辑里，读不出来」 | 不显示等于消失，用户会以为我们的表和游戏不一致 |
| 10 | 属性中文名**人工建 6–8 项小表** | 资产里没有集中的属性名清单；游戏面板的显示名硬编码在蓝图字节码里 |
| 11 | 「计算模型是我们推的」写在**抽屉数值段底部**小字 | 用户看数字的地方就在那，提示必须同屏 |
| 12 | M0 通过线：**至少 4 项在八成以上武器上可读**就做 L2 | 全有才做太脆，任何一把枪缺一个字段就全盘作废；部分成功也能交 |
| 13 | 乘算叠加按**增量相加**：`1 + Σ(m−1)` | 与决策 4 同义；逐个相乘会让第二件改装看起来变弱 |
| 14 | 转管机枪射速写「**1.0（起步 3.4，加速上限读不出）**」 | 只写 1.0 是错的，玩家一开枪就是 3.4；给假数字比说读不出更糟 |
| 15 | 属性只六项，精度 / 后坐力不进本版 | 它们散在 `EHitScanBaseUpgradeType` 里、字段名不统一，会是第二个「伤害取哪个组件」 |

## §1 数据契约

### 1.1 武器基础数值 `app/src/data/weapon-stats.json`

```jsonc
{
  "$source": "游戏 pak 里 WPN_* 资产的 CDO 与伤害组件（明文 Int/Float 属性）",
  "$notice": "只含数值，不含任何游戏资源",
  "weapons": {
    "<武器 SaveGameID>": {
      "folder": "FlameThrower",
      "stats": {
        "damage":  { "value": 11.0, "component": "Damage", "kind": "direct" },
        "clip":    50,
        "ammo":    300,
        "rof":     6.0,
        "reload":  3.0,
        "range":   1000.0
      },
      "missing": [],                 // 读不出的项，键名同上
      "notes": [],                   // 需要解释的项，如转管机枪的射速
      "damageComponents": [          // 全部伤害组件，折叠区展示
        { "name": "Damage", "damage": 11.0 },
        { "name": "AoEHeatDamage", "radial": 80.0 }
      ]
    }
  }
}
```

- 六项缺哪项就进 `missing`，不补 0、不猜
- `notes` 里放需要一句人话解释的例外（决策 14）

### 1.2 改装数值效果 `app/src/data/upgrade-effects.json`

```jsonc
{
  "$source": "游戏 pak 里 UPG_* 资产的 Amount / IsPercentage / UpgradeType / Category",
  "effects": {
    "<改装 SaveGameID>": {
      "stat": "clip",              // 六项之一；对不上就是 null
      "amount": 25.0,
      "mode": "add",               // add | mult | unknown
      "source": "UpgradeType::ClipSize"
    }
  }
}
```

- `mode: "add"` — 资产没有 `IsPercentage`，`amount` 直接加
- `mode: "mult"` — `IsPercentage=true`，**`amount` 是倍率本身**（`0.73` = 变成 0.73 倍）
- `mode: "unknown"` — 43 条没数值字段的、14 条资产未解包的，统一写这个，界面按决策 9 显示
- `stat` 对不上六项的（比如装甲容量）也标 `unknown`，并留 `source` 说明它本来是什么

## §2 计算模型（写死，可单测）

对每一项属性：

```
结果 = 基础值 × (1 + Σ(该属性的 mult 系数 − 1)) + Σ(该属性的 add 值)
```

- 没有该属性的改装 → 结果 = 基础值，界面只显示一个数（不写 `42 → 42`）
- 结果与基础值相同（浮点比较留 1e-6 容差）→ 也按「无变化」渲染
- 装填时间这类「越小越好」的属性，算法不变，靠数值本身表达（`3.0 → 2.19`）

**这个公式是我们推的，不是从游戏里读出来的。**决策 11 要求界面上写明。

## §3 里程碑

### M0 · 可读性验证（1 天，**先验关卡**）

- 写一个**真解析器**读 34 个 `WPN_*` 资产（不是 `grep`——属性名走 name table 索引，字符串搜不到）
- 逐把枪统计六项的可读情况，产出 `_tools/v0.3.0-数值可读性报告.md`：每把枪 × 每项一张表，标「读到值 / 读不出 / 需要解释」
- 同时抽 `UPG_*` 的 `Amount` / `IsPercentage` / `UpgradeType` / `Category`，统计 398 条武器改装里有多少条能落到六项上
- **通过线**：至少 4 项在 80% 以上武器上可读
- **不通过**：立刻停下报数，本版退成「只显示武器基础数值 + 改装名清单」，不做堆叠。**不许自己降级，必须报。**

### M1 · 抽两张表（1.5 天）

按 §1 产出 `weapon-stats.json` 与 `upgrade-effects.json`，每条带 `$source`；43 条无条件与 14 条未解包的显式标 `unknown` 并注明原因。

### M2 · 计算与命令（1 天）

后端新增只读命令 `simulate_loadout(weapon_id, upgrade_ids) -> Vec<StatRow>`，返回六项各自的 `{ key, base, value, changed }`。纯函数，单测覆盖 §2 的每条规则（含 mult 增量相加、add 后置、无变化判定、缺项）。

### M3 · 界面（1.5 天）

- 武器抽屉里加「数值」段：顶部六项并排，变化的写 `42 → 47.0` 并把新值高亮
- 改装清单每条加可点状态：**已解锁且未装**的可点（点了就试装），已装的再点取消；未解锁的不可点
- 被试装的条目要能看出来「这是模拟，不是你真装着的」
- 没有数值效果的改装点开显示决策 9 的那句话
- 段底一行小字：计算模型说明

### M4 · 回归与门禁（1 天）

新增场景：打开抽屉看到六项 / 点已解锁改装数值变化 / 取消后回到原值 / 未解锁不可点 / 无效果改装显示那句话 / 转管机枪射速的例外文案。

门禁照跑 `--with-stock`，游戏目录前后 `diff` 必须 `IDENTICAL`。

### M5 · 出包发布（0.5 天）

合计约 **6.5 天**。

## §4 验收（可演示）

1. 打开一把枪的抽屉，看到六项数值；装着改装的那几项显示 `基础值 → 新值`
2. 点一条已解锁但没装的改装 → 数值立刻变；再点一次 → 回到原值
3. 未解锁的改装点不动
4. 43 条没有数值效果的改装，点开写「这条的效果在游戏逻辑里，读不出来」
5. 转管机枪的射速写「1.0（起步 3.4，加速上限读不出）」
6. 数值段底部有计算模型说明
7. 全程不写存档：跑前跑后存档文件 sha256 一致

## §5 明确不做

- 不算 DPS、不乘弱点倍率、不滤护甲、不算距离衰减与状态效果
- 不做 A/B 配装对比
- 不允许模拟未解锁的改装
- 不做精度 / 后坐力等六项之外的属性
- 不把试装结果写进存档（**永久红线**）

## §6 风险

1. **伤害口径可能与游戏面板不一致**：转管机枪有 `Hitscan 17.0` / `Damage 14.0` / `RadialDamage 9.0` 三处，我们取直击，游戏面板可能取别的。界面上必须注明取的是哪个组件。
2. **计算模型是我们推的**：游戏真实公式如果是逐条相乘，我们会算得偏高。界面上写明，且这是「模拟」不是「权威」。
3. **43 条改装没有数值字段**（效果写在蓝图里）、**14 条资产未解包**——这些在界面上只能诚实说读不出。
4. **转管机枪的射速上限读不出**（依赖未解包的 `Curve_AutoCannon_ROF`）。
5. 属性名是我们起的，可能与游戏内用词不同（比如游戏叫「弹匣容量」我们叫「弹匣」）。

## §7 红线

- **只读**：不写存档、不碰游戏目录、不改 `mods_P.pak`
- 试装是纯前端 + 后端纯计算，不产生任何持久化副作用
- 六项属性名与计算模型必须写进 `文档/`，不能只活在代码里
- 界面不出现 `UPG_`、`CDO`、`IsPercentage` 这类词

## §9 M0 报告模板

`_tools/v0.3.0-数值可读性报告.md` 必须含：

1. 34 把武器逐把的六项可读表（读到值 / 读不出 / 需要解释）
2. 六项各自的「可读武器数 / 总武器数」
3. 398 条改装落到六项上的统计：能算出 `add` 的、能算出 `mult` 的、`unknown` 的
4. 一句结论：**通过 / 不通过**，以及按决策 12 的门槛算出的是多少
5. 三个「需要人工定规则」的问题清单（伤害取哪个组件、射速斜坡、属性名对照）

> **不许用 `grep` 估算覆盖率。**属性名走 name table 索引，字符串搜不到——用字符串统计会得出「只有 2 把枪有弹匣字段」这种结论，把一个能做的版本做废掉。
