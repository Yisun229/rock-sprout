# v0.1.7 实施计划

> **依据**：`文档\路线图-v0.1到v1.0.md` §4「v0.1.7 深挖」
> **这一版要做成的三件事**：① 玩家不用自己去装 UE4SS；② 脚本类 mod 能装上并生效；③ 装了 mod 之后，有新版本能一键换掉。

这一版是 mod 主线的最后一块。做完之后，`背包`、`矿脉`、`今天` 三个页面就是完整闭环；再往后才是看板、联机、存档分析那些「伴侣」功能。

## 1. 要做的

### M7-0 先把事实钉死（0.5 天，**必须最先做**）

三件事决定后面怎么走，没做完不动代码：

1. **拉 10–20 个 mod.io 上的 DRG 脚本类 mod，拆包看内容**：`Scripts\main.lua` 占多少、有没有 `main.js` 之类。结论决定 M7-4 做不做 JS。
2. **在 DRG 上实测官方 `override.txt`**：把 UE4SS 核心放进 `Win64\ue4ss\`、根目录只留 `dwmapi.dll`，看 UE4SS 能不能正常加载（看它自己的日志）。决定 M7-2 用子目录还是平铺。
3. **记录 `UE4SS.log` 的关键行格式**：哪一行代表「加载成功」、哪一行代表「没加载」。这是 M7-3 的判据。

**验收**：一份不超过一页的记录，三项各一行结论；不确定的写「未验证」，不许写推测。

### M7-0b 扩样（0.5 天，**不阻塞开工**）

去留已经定了（做），这一步不再是判决关卡，目的换成两件：

- **把识别逻辑的夹具补厚**：现有 26 个样本只取了「热门」，脚本类样本只有 1 个。再加一组——按 `_sort=-date_added` 取前 30、下载量前 30，与已有 26 个去重合并后 **≥ 60**
- **摸清脚本类的形状分布**：逐包统计 `.pak` / `main.dll` / `main.lua` / `main.js` / `Scripts/`，以及「同时带 pak 和 main.dll」这种混合形状有多少

**它不再阻塞 M7-1～M7-4**，可以和 M7-1 并行做。产出的比例表只作参考，不再作为砍功能的依据。

**验收**：一张比例表 + 一句话结论 + 样本包保留在 `_tools\u4ss-sample`（回归夹具，不许删）。

### M7-1 下载与校验（1 天）

- 版本号 `v3.0.1`、下载地址、**sha256 写死在代码里**，不接受动态获取
- 5.5 MB 下载要有进度、可取消、失败可重试
- 下载失败或校验不通过 → 给「手动下载」入口 + 一句「下好之后放到这个目录」
- 校验通过后**先解压到临时目录验证结构**（`dwmapi.dll` / `UE4SS.dll` / `UE4SS-settings.ini` / `Mods\` 齐了），再往游戏目录动

**验收**：断网时点「装 UE4SS」→ 出现手动下载入口和路径说明，不出现英文报错。

### M7-2 安装与卸载（2 天）

**装之前的四道检查**，任一条不过就停下说清楚：

1. 游戏没在运行（复用现有 `blocked_by_running_game`）
2. `Win64` 里没有同名冲突：`dwmapi.dll` 若已存在且**不是我们装的**，先走第 4 条
3. 磁盘空间 ≥ 100 MB
4. **检测到已有别的 UE4SS**（例如 `ue4ss\UE4SSL.dll`）→ 弹「这台机器上有一套别的工具装的 UE4SS，要不要换成官方的」，同意后**先备份**（`dwmapi.dll` + `ue4ss\` 目录）再动；弹窗里要写明「换成官方版后，原来那套里的脚本 mod 需要重新装一遍」（MintCat 的定制包带自己的 JS 框架，换了以后它的 mod 不一定还能跑）

**写入流程**：备份 → 写文件 → 逐个校验合并后的状态 → 任一步失败**全部还原**。这套机制 v0.1.1 卸载时已经做过，复用，不写第二套。

**卸载**：按安装时记下的文件清单逐项删；`Mods\` 目录里**用户自己放的东西不盲删**（只删我们登记的条目；有内容就整目录挪进备份，不删）。

**卸载还要认「运行期自己长出来的文件」**：`UE4SS.log`、`UE4SS-settings.ini.bak`、`CrashDumps\` 这些不在安装清单里，是 UE4SS 跑起来之后自己写的。漏删就会在用户游戏目录留垃圾——M7-2 实测那份快照 `13 → 32 → 14 → 13` 里，多出来的那一个就是它（详见 §0 第 29 条）。

**验收**：装 → 验 → 卸，`Win64` 目录的字节级快照与装之前一致。

### M7-3 生效检测（1 天，**不可砍**）

**为什么不可砍**：MintCat 能在游戏更新后自己修好，是因为它有服务器——启动时比对自家清单里的版本号（`ue4ssl` / `drg` / `rc` 三个 appType），发现新包就覆盖安装，客户端根本不需要知道游戏更没更新。我们没有服务器，就没有这条回退通道，失效只能靠本地发现。**这是唯一的补偿。**

- 游戏启动后读 `UE4SS.log`，判断最近一次启动有没有「加载成功」那行
- 判据写死：日志里存在**晚于本次游戏启动时间**的 `Event loop start`；不许模糊匹配一大片
- **日志时间是 UTC**，比较前先把自己取的本地启动时间转成 UTC。M7-2 实测：日志写 `07:24` 而本地是 `15:24`，按本地时间比会永远判成「没加载」
- 结论变成「今天」页的一条：成功不显示；失效显示「UE4SS 没生效，可能是游戏更新了，点这里重装」
- 重装 = 用本地钉死版本的包重铺一遍（不联网也要能用）；铺之前**先备份**已有的 `dwmapi.dll` / `UE4SS.dll` / `UE4SS-settings.ini`（学 MintCat 的做法）
- UE4SS 根本没装时不检测、不显示

**验收**：人为把 `UE4SS.dll` 改名 → 启动游戏 → 「今天」页出现失效提示；改回来并重启 → 提示消失。断网状态下点「重装」也能成功。

### M7-4 脚本类 mod 的安装路径（2 天）

**现在的问题**：`local.rs:237-249` 对「没有 pak 的文件夹」是**整个打成 pak**，所以现在把脚本 mod 丢进来，会被塞进 `mods_P.pak`，装完一定不生效（`integrate.rs` 全程没有内容类型分支）。

- 新增判定：包内含 `main.dll` / `main.lua` / `main.js` → 脚本类（不按 `Scripts/` 目录判，见 §0 第 20 条）
- 脚本类**不进 pak 合并**，落到 `ue4ss\Mods\<名字>\`
- 同名目录已存在时**不覆盖**：报「已经有一个同名目录」，给「换一个名字」或「替换（先备份）」两个选择
- 装之前核对 `UE4SS-settings.ini` 里指向 mods 的那一项确实是我们铺的 `Mods\`，别被别的 UE4SS 配置带偏
- 这类 mod 在 `背包` 里要能看出是「脚本类」（避免用户以为它和 pak mod 一样）
- 卸载 = 只删我们登记的那个目录，`Mods\` 里别人的东西一概不动

**验收**（两条，一条证成功、一条证失败，缺一不可）：

1. **成功链路**：Lua 夹具（`Scripts/main.lua` + `enabled.txt`）装进去 → 启动 → 日志出现 `Starting Lua mod '<名字>'` 与 `[Lua] [<名字>]` 输出 → 背包标「脚本类」且状态为已生效
2. **失败链路**：真样本 `_tools\u4ss-sample\4454464.zip` 装进去 → 启动 → 日志出现 `Failed to load dll … error code: 0x7e` → 背包显示「没生效」并把原因翻成人话（见 §0 第 35、36 条）

**只看目录建对了不算验完**（§0 第 33 条）。

> 实测背景：3.0.1 的日志里**没有** `Load Mod '<名字>'` 这种写法。真实只有三种：`Mod 'X' has enabled.txt, starting mod.`、`Starting Lua mod 'X'`、`Failed to load dll <路径> for mod X, error code: 0xNN`。判据必须按实测写。

### M7-5 mod 一键升级（1.5 天）

- 「今天」页现有的「有新版本」从提示变成「一键换新版」
- 换的时候：下载新包 → 校验 → 写临时名 → 原子改名替换 → 成功后才改记账；失败留旧包（见 §0 第 24 条）
- 「今天」页优先列出可更新的 mod，每行一个「更新」，底部一个「全部更新」
- 只对 `source = modio` 的 mod 生效，本地导入的不显示

**验收**：真换一次，换完 `file_id` 更新、游戏里能进。

### M7-6 说明、回归、出包（1.5 天）

安装 UE4SS 前的那一次弹窗，三句话定稿：

> 1. UE4SS 是一段注入游戏进程的脚本加载器，装在游戏的 `Binaries\Win64` 里，只影响这台电脑。
> 2. 装好之后，**游戏里的 mod 列表看不见它管的东西**——那是游戏自带的另一套系统。要卸载只能从这个程序里卸。
> 3. 联机：DRG 官方只认它自己那套 mod 体系，注入类的改动不在它的名单里。你想在联机时用不用，自己决定。

Release 说明补三条：游戏内列表看不到是正常的、只能从我们这里卸、UE4SS 是什么。

**回归**：现有 90 场景 + 新增（下载失败 / 校验失败 / 撞名拒装 / 已装 MintCat 版提示 / 脚本类识别 / 脚本类卸载 / 失效检测 / 一键升级）。

## 2. 不做

- **JS 脚本 mod**（MintCat 那套 `UE4SSL.JavaScript`）——不接第三方定制注入器
- **UE4SS 自动更新**——锁版本，只在失效时提示
- **多版本并存**
- **改 `dwmapi.dll` 或维护自己的 UE4SS 分支**
- **汉化脚本 mod 的内容**（v0.1.6 的翻译只覆盖 mod 简介）
- **游戏内列表联动**——那是另一套系统，碰不到

## 6. 依据：为什么 M7-3 不可砍、为什么判据按 `main.dll`

**一、官方 mod 系统装不了脚本类 mod**

- `FSD\Mods`（游戏内 mod 菜单的落地目录）本机只有 `ChatManager`、`DRGLib`
- `enemy-wave-timer` 不在那儿，它在 `FSD\Binaries\Win64\ue4ss\mods\`
- `UE4SS.log` 三条：
  - `[2026-10-30 14:40:36] Install mod 'enemy-wave-timer'.`
  - `[2026-10-30 14:40:36] Load Mod 'enemy-wave-timer' , starting mod.`
  - `[2026-10-30 14:41:10] Object Name: Function /Game/EnemyWaveTimer/WaveTimer.WaveTimer_C:GetWaveTimes`
- 结论：官方系统只吃它自己格式的 pak、**不执行 DLL**；`Enemy Wave Timer` 这种「pak + `main.dll`」的包，在游戏内订阅装不进去核心逻辑。所以「有没有 pak」不能当判据（§0 第 20 条）。

**二、MintCat 的更新模型（读它热更新后的前端源码得出）**

- 启动自更新：`StartupUpdateCheckTask` 按 `name` / `type` / `channel` 找 `mintcat-frontend`、`mintcat-integrator`、`mintcat-proxy`，版本号更大就下载安装
- UE4SS 走另一套：`Ue4ssSetting` 在缓存目录维护 `manifest.json`（字段 `{ue4ssl, drg, rc, channel}`），调 `checkInternalAssetsForUpdates([{currentVersion, appType:"ue4ssl"}, {currentVersion, appType:"drg"}])`，拿到 `latestVersion` + `md5` 才下载 `UE4SSL.zip`
- `drg` 这个 appType 说明它给「给 DRG 用的内部资源」单独编版本：游戏更新后它发新版，客户端下次启动自动换
- **它不检测游戏更新，检测的是自家清单版本号**；代价是强依赖自家服务器

**三、它做对的地方（要学）**

- 装 UE4SS 前先备份已有文件：`C:\Users\admin\AppData\Roaming\com.mint.cat\ue4ss-backup\20261026-204118\{dwmapi.dll, UE4SSL.dll, UE4SS-settings.ini}`
- 游戏目录里的 `.mintcat-ue4ss.json` 记着 `version: ue4ss-3.0.1-proxy`、`installedAt`、`proxyExisted` / `coreExisted` / `settingsExisted` 与三份备份路径

**四、对决策的影响**

- 我们没有服务器 → 失效检测是唯一补偿 → **M7-3 不可砍**
- 「有 pak」不等于「不是脚本类」 → 判据按 `main.dll` / `main.lua` / `main.js`

## 7. 依据：DRG 的 C++ 脚本 mod 生态挂在 UE4SSL 上

M7-4 实跑时拿 `4454464`（Enemy Wave Timer，mod.io 上热门的 C++ 脚本 mod 之一）当样本，装法验证是对的，但 dll 载不进去：

```
[2026-10-31 09:56:12] Failed to load dll <…\Mods\4454464\dlls\main.dll> for mod 4454464, error code: 0x7e
[2026-10-31 09:56:12] Was unable to install mod '4454464' for unknown reasons. Mod is not installable.
```

`0x7e` = 找不到模块。扒样本 dll 的字符串：**它导入 `UE4SSL.dll`**，编译路径是 `D:\Project\UE4SS-Lite\…\WaveTimer.pdb`——给 MintCat 那个 fork（UE4SSL）编的，不是给官方 UE4SS 编的。

同一轮的反证：临时手放一个 Lua 探针 mod（`Scripts/main.lua` + 空 `enabled.txt`），启动后日志是

```
Mod 'ProSproutProbe' has enabled.txt, starting mod.
[Lua] [ProSproutProbe] hello from lua
```

说明我们的铺法（`Mods\<名字>\` + `enabled.txt` + 3.0.1 要求的 `dlls\main.dll` 子目录）是对的，卡住的是那个 dll 自己的依赖。

**结论与后果**

- mod.io 上至少有一部分 C++ 脚本 mod 是**为 UE4SSL 编的**，官方 UE4SS 装不上。这不是我们的 bug，是这个 mod 的依赖问题
- 我们**不改用 UE4SSL**：那是别人改过的 fork，来源与维护都不在我们手上，不能拿来当发行依赖
- 所以 M7-4 的真正价值 = 「Lua 能用」+「C++ 装不上的时候能说清为什么」。后者正是 §0 第 21 条（界面不许静默失败）最典型的一次应用
- 官方格式的 C++ mod 能不能用，**我们目前没有样本，不下结论**；有样本之前不写进说明
