## 3. 每个阶段怎么做

### M0a · 现成版验证（半天）

**目的**：回答一个问题——mint 的安装逻辑在我们这台机器上到底管不管用。

**步骤**

1. 拉源码（只读参考，不改）
   ```bat
   git clone --depth 1 https://github.com/trumank/mint "E:\岩笋 · Rock Sprout\ref\mint"
   ```
2. 去 GitHub Releases 下载最新版 `mint-*.exe`
3. 运行它，指向 `d:\steam\steamapps\common\Deep Rock Galactic`
4. 在 mod.io 上挑一个简单的 pak 类 mod，用它装上
5. 启动游戏，确认 mod 生效

**要顺手记下的四件事**

- 需要 Steam 客户端开着吗？
- 需要先装 UE4SS 吗？
- mod 最终装在哪个目录？
- 搜索和下载在这台机器上的网速如何？

**判断**

| 结果 | 下一步 |
|---|---|
| 能装、能生效 | 进 M0b |
| 能装但不生效 | 先查 pak 路径与 Steam 完整性，可能换安装策略 |
| 装不上 | 整个计划的风险等级上调，需要重估底座 |

### M0b · 工具链（1–2 小时，含下载）

> **状态：已完成。** 实际装完的版本、路径、编译耗时和踩到的坑都记在 §10。

**步骤**

1. 装 Rust（**先设环境变量再装**，否则会写到 C 盘）
   ```bat
   setx RUSTUP_HOME "E:\岩笋 · Rock Sprout\_tools\rust"
   setx CARGO_HOME  "E:\岩笋 · Rock Sprout\_tools\rust"
   setx CARGO_TARGET_DIR "E:\岩笋 · Rock Sprout\_tools\target"
   ```
   重开终端，然后装 rustup，工具链选 **nightly**（`nightly-x86_64-pc-windows-msvc`）——mint 自带 `rust-toolchain.toml` 指定 nightly，用 stable 编不过。

2. 装 VS Build Tools，勾选「使用 C++ 的桌面开发」
   安装路径改到 `E:\岩笋 · Rock Sprout\_tools\vs`（安装器本体仍会占 C 盘 1–2 GB）

3. 编译 mint
   ```bat
   cd "E:\岩笋 · Rock Sprout\ref\mint"
   cargo build --release
   ```

4. **关键验证**：`mint_lib` 能不能脱离 egui 用
   - 看 `mint_lib` 的公开类型里有没有 egui 的类型
   - 如果有，记录是哪几个，评估拆解成本

**判断**

| 结果 | 影响 |
|---|---|
| 干净可用 | 直接当 crate 依赖 |
| 有轻微耦合 | fork 到 `app/vendor/` 去耦合（MIT 允许） |
| 重度耦合 | 只抽出 pak 合并那一块，其余自写 |

### M1 · 工程骨架（1 周）

**目标**：空壳能跑，按钮能调通后端。

**步骤**

1. 建工程。这台机器 `npm`/`npx` 坏了，`pnpm create tauri-app` 走不通，所以工程是手工照 Tauri 2 的标准结构搭出来的，`app\` 目录已经是成品，不必再生成。

   **必须用 `node <路径>/pnpm.cjs` 调 pnpm**，直接敲 `pnpm` 会捡到 PATH 里那个版本对不上的外壳：
   ```bat
   node D:\DSH-X\node\node_modules\pnpm\bin\pnpm.cjs install
   node D:\DSH-X\node\node_modules\pnpm\bin\pnpm.cjs run build
   node node_modules\@tauri-apps\cli\tauri.js build --no-bundle
   ```
2. 目录约定（已落地）
   ```
   app\
   ├── src\            前端（React）  App.tsx / main.tsx / styles.css
   └── src-tauri\
       ├── src\        后端（Rust）
       │   ├── main.rs      注册命令 + 启动
       │   ├── ipc\         命令层，一个文件一组（mods.rs / game.rs）
       │   ├── paths.rs     数据目录（跟着 exe 走，不写 C 盘）
       │   └── logging.rs   日志写到 <数据目录>\logs\
       └── Cargo.toml
   ```
3. 先定六个命令（只留骨架，返回假数据）
   - `search_mods(query, page)`
   - `get_mod_detail(id)`
   - `install_mod(id)`
   - `uninstall_mod(id)`
   - `list_installed()`
   - `launch_game()`
4. 端口径：所有命令统一返回 `{ ok, data, error }`，不要让它以后各写各的

**通过标志**：前端点一个按钮，能拿到后端返回的假数据。

**实测记录**：见 §11。

### M2 · mod.io 客户端（1 周）

**目标**：命令行里跑完「搜到 → 看详情 → 下载」整个流程。

**步骤**

1. `ModioClient::get_me(token)` → 拿到**你自己的 uid**（这是和 MintCat 的关键差异）
2. 主机地址用 `https://u-{uid}.modapi.io/v1`，`game_id = 2475`（**这个数字只出现在一个常量里**）
3. 搜索：`/games/2475/mods?name_id=...&_sort=-downloads`
4. 详情：`/games/2475/mods/{id}`
5. 下载：先拿 `/files`，再下 download url
6. 限速：全局串行队列 + 每请求间隔，429 时读 `Retry-After` 退避

**通过标志**：不启动界面，用 `cargo run --bin peek -- <关键词>` 能列出结果并下载一个文件。

### M4 · 失败态与缓存（3–5 天）

**错误必须分开处理**

| 情况 | 提示 | 用户能做什么 |
|---|---|---|
| 401 | 令牌无效或过期 | 重新获取令牌（给链接） |
| 429 | 请求太快，第 N 秒后自动重试 | 等待，自动继续 |
| 超时 / 断网 | 连不上 mod.io | 重试 / 改用离线导入 |
| 磁盘满 | 空间不足 | 提示需要多少 |

**本地缓存**：列表与详情存本地，断网时仍能浏览、卸载。

**通过标志**：拔网线，程序能正常打开并显示上次的列表。

## 9. 参考基线（mint）

源码放在 `ref\mint`，**只读参考，一律不修改**。记录时间 2026-10-28。

| 项 | 值 |
|---|---|
| 仓库 | `https://github.com/trumank/mint` |
| 提交 | `57aa964e7789f132481813a8f4b5781f924eccd1`（2025-12-16，`Fix modding tab crash`） |
| 版本 | `0.2.10`，`edition 2024` |
| 许可证 | MIT（`Copyright (c) 2023 Truman Kilen`） |
| 工具链 | **nightly**（仓库自带 `rust-toolchain.toml`），stable 编不过 |
| 编译期网络 | 依赖 `patternsleuth`、`repak` 两个 git 依赖，编译时必须能访问 GitHub |

用到的两条外部事实（写代码时只放一处常量）：

- mod.io 的 DRG 游戏号是 `2475`，在 mint 里出现于 `src/providers/modio.rs:46`（`MODIO_DRG_ID`）
- Steam 版游戏可执行文件名 `FSD-Win64-Shipping.exe`，pak 名 `FSD-WindowsNoEditor.pak`

### 9.1 代码分布（决定「能拿什么」）

| 目录 | 行数量级 | 里面是什么 |
|---|---|---|
| `mint_lib/src/`（4 个文件） | 约 200 行 | 游戏安装位置探测、mod 元信息、版本检查、错误类型。**不含界面代码** |
| `src/providers/modio.rs` | 1208 行 | mod.io 全部接口调用（搜索 / 详情 / 文件 / 下载） |
| `src/integrate.rs` | 1268 行 | 装进游戏的真正逻辑：pak 合并、冲突检测、卸载还原 |
| `src/state/mod.rs` | 706 行 | 已装状态、队列、配置 |
| `src/gui/mod.rs` | 2174 行 | 界面（egui），我们一点都用不上 |

**要点**：`mint_lib` 只是一层薄壳，真正值钱的 mod.io 客户端和 pak 合并都写在**应用 crate 里**，和 egui 界面同一个包。所以「把 mint_lib 当依赖就能装 mod」这个假设不成立，具体走哪条路见下一节的结论。

### 9.2 底座策略：拿哪部分、自己写哪部分

**结论：只搬两块代码过来（pak 合并 + 安装前检查），mod.io 客户端和状态管理自己写。**

| 部分 | 怎么处理 | 理由 |
|---|---|---|
| `mint_lib`（约 200 行） | **搬** | 找游戏装在哪、mod 元信息、写进 pak 的元数据结构。都是纯逻辑，没有界面代码 |
| `src/integrate.rs`（1268 行） | **搬** | pak 合并、覆盖顺序、卸载还原。这是整个项目最难写的一段，重写不划算 |
| `src/mod_lints/`（328 行） | **搬** | 装之前检查：pak 版本对不对、有没有冲突、有没有多余文件 |
| `hook/` 与 `hook_resolvers/`（游戏内加载器 DLL） | **搬** | 游戏里能不能认出 mod 靠它。新版 pak 必须配新版 DLL，两者得同源 |
| `assets/integration/`（94 个文件） | **搬** | 游戏内那套 mod 菜单用的资源，`integrate.rs` 会把它们打进 pak |
| mod.io 客户端（`src/providers/modio.rs`） | **自己写** | 它绑了作者自己改的 modio 库（git 分支，不锁版本），而且没做「令牌换真 uid」这件事 |
| 已装状态与配置（`src/state/`，706 行） | **自己写** | 它带一整套「档位（profile）」概念，我们 v0.1 三页界面用不上 |
| 界面（`src/gui/`，2174 行） | **不碰** | 法律和品牌都不允许 |
| 顶层编排（`src/lib.rs`，247 行） | **自己写** | 我们的入口是 Tauri 命令层，结构完全不同 |

搬到哪（这就是现在的实际位置）：

| 搬来的东西 | 落在 |
|---|---|
| pak 合并与检查逻辑 | `app\src-tauri\src\integrate.rs`、`src\mod_lints\`、`src\providers.rs`（类型垫片） |
| 找游戏在哪 + mod 元数据结构 | `app\src-tauri\mint_lib\`（独立小 crate，因为加载器 DLL 也要用它） |
| 加载器 DLL | `app\src-tauri\hook\`、`app\src-tauri\hook_resolvers\` |
| 游戏内菜单资源 | `app\src-tauri\assets\integration\` |

许可证与出处：`app\src-tauri\LICENSE-MINT`（MIT，`Copyright (c) 2023 Truman Kilen`），每个搬来的文件头都写明来源与提交号。

**这条路要付的三笔账**

1. `integrate.rs` 要用到几个来自 `providers` 的类型（`ModInfo`、`ReadSeek`、`ProviderError`）。搬过来时补一个几十行的类型垫片即可，不用把整个 `providers` 搬来。
2. 这几块代码用了 nightly 编译器特性（1 处 `#![feature(if_let_guard)]` + 13 处 if-let 链写法）。要么整体用 nightly 编译，要么把这 13 处改回普通写法——**建议先按 nightly 编过，跑通再说**，别在第一步就改别人的代码。
3. mod.io 那套库依赖运行时要能访问 GitHub（`patternsleuth`、`repak` 等 git 依赖）。这些是编译期依赖，编好之后就没事了。

**另一件要你拍板的事（不影响当前进度）**

**四个待答问题的结论**

| 问题 | 结论 |
|---|---|
| 要不要开 Steam | 要。游戏是 Steam 版，mint 的 `launch` 子命令也是「通过 Steam 启动」 |
| 要不要先装 UE4SS | 不要。pak 类 mod 直接合进资源包，UE4SS 只服务 Lua/JS 类 mod，两条平行线 |

| 搜索下载速度 | 没测到。mod.io 从这台机器连不上，图形界面的搜索/下载没走通 |

**测试现场已还原**：`FSD-WindowsNoEditor_Mods.pak` 改回原名（156,325,146 字节）、`x3daudio1_7.dll` 换回原文件（386,560 字节）、mint 生成的测试包留档在 `_tools\game-backup\mint-test-留档\mods_P.pak`。

| 地址 | 结果 | 说明 |
|---|---|---|
| `https://api.mod.io/v1/games/2475` | HTTP 401，0.6–0.8 秒 | 通了，只是没带 api_key |

### 12.3 踩过的三个坑

1. **自带的证书清单不认本地加速工具的证书**。一开始 HTTP 库用的是内置根证书（rustls），代理工具一替换证书就握手失败，报的还是一句含糊的「error sending request」。换成走 **Windows 系统证书库**（native-tls / Schannel）后立刻就通了。凡是用户可能开代理（国内很常见），这一点必须这么办。
2. **30 秒超时不够**。同一个接口有一次 28.35 秒才回，等于卡在边缘。现在接口给 90 秒；下载单独一个客户端、**不设总时长上限**（只限制「连上」的时间），否则大 mod 传到一半会被掐断。
3. **mod.io 的搜索参数是 `_q`，不是 `name`**。`name` 是精确匹配——搜「drill」返回 0 条；换成 `_q` 才有结果。这条当初按文档想当然写错了，是拿真接口试出来的。

## 13. 装 mod 进游戏这条链路（实测记录，已完成）

这一节说的是：**从「有个压缩包」到「游戏里真的能玩」**。现在这条链路完全由本工程自己完成，不再调用 mint 的现成程序。

### 13.1 一次安装具体做了什么

| 步骤 | 做什么 | 落在哪 |
|---|---|---|
| 1 | 找游戏装在哪（只支持 Steam 版，靠 Steam 库记录找 appid 548430） | 读游戏目录 |
| 2 | 把 mod 压缩包解开、连同游戏原有资源一起合并 | 临时内存 |
| 3 | 写出合并后的包 | `<游戏>\FSD\Content\Paks\mods_P.pak` |
| 4 | 写出加载器 DLL（游戏靠它在启动时读我们的包） | `<游戏>\FSD\Binaries\Win64\x3daudio1_7.dll` |

DLL 内容在编译时就被塞进了主程序内部，运行时才写出来——所以对外只发一个 exe 就够，用户不用手动放文件。

### 13.2 实测数字（2026-10-28）

| 项 | 值 |
|---|---|
| 测试 mod | mod.io 上的 Brighter Objects 1.12.3（462,029 字节的 zip） |
| 合并后的包 | 5,160,222 字节 |
| 加载器 DLL | 4,128,256 字节 |
| 整个安装耗时 | 约 0.53 秒 |
| 游戏内结果 | **能看到 mod、启用后有实际效果**（用户确认） |

### 13.3 为什么我们的包比 mint 官方 exe 装出来的大 2.8 MB

一开始以为是写错了，把两个包逐条对比后才明白：**是 mint 的发布版太老，不是我们多写了东西。**

| 对比项 | mint 官方 0.2.10 发布版 | 我们（源码提交 57aa964） |
|---|---|---|
| 游戏内菜单资源 | 14 个旧文件（`MI_Mod`、`MI_UI_Mod`、`test.umap`…） | 94 个新文件（`_mint/BPL_MINT`、`JSON/`、`Sorting/`、`UI/`…） |
| 记录已装 mod 的 `meta` | 没有 | 有（游戏靠它列 mod） |
| 资源总表 `AssetRegistry.bin` | 没有 | 有 |
| mod 本体的 12 个文件 | 名字、大小都一样 | 名字、大小都一样 |

mint 的 CHANGELOG 里「Unreleased」一段写着 “Implement Asset Registry handling”，说明这套新资源是发布之后才提交的。**我们跟源码走**，因为旧版对不少 mod 支持不全。

### 13.4 因此必须一起搬的东西

新版 pak 配旧版 DLL 是不行的——DLL 要在游戏启动时读 pak 里的 `meta`。所以加载器 DLL 也一起搬了进来：

- `app\src-tauri\hook\`、`hook_resolvers\`：编成一个 DLL
- `app\src-tauri\Cargo.toml` 改成工作区（4 个成员：主程序、`mint_lib`、`hook`、`hook_resolvers`），默认开 `hook` 特性
- `app\src-tauri\.cargo\config.toml`：打开 nightly 的 `bindeps`（把 DLL 编出来嵌进 exe 的开关，官方要求显式打开）

### 13.5 踩过的坑

1. **`[target.'cfg(...)'.dependencies]` 写在文件中间会把后面的依赖全吞掉。** 症状是 `unresolved import repak / snafu / fs_err` 一片红。这类平台相关的依赖段必须放在文件最末尾。
2. **artifact 依赖不认 `cargo build`**，报 `` `artifact = …` requires `-Z bindeps` ``。解法是 `.cargo/config.toml` 里写 `[unstable] bindeps = true`。
3. **`unreal_asset` 出现两份**会报 `multiple different versions of crate unreal_asset` 加一堆类型不匹配。必须和 mint 锁定同一个来源：`branch = "patches"`（不是 `rev`），否则 `uasset_utils` 里那份和我们这份成了两个包。
4. **`repak` 不能用默认分支**，新版接口从 2 个参数变成 3 个，得钉到 mint 的 `Cargo.lock` 里那个提交。
5. **测试时 mod 名字显示成「命令行装的测试mod」**：那是命令行自测工具里硬写的占位名，不是 bug；正式装的时候名字来自 mod.io 的数据。

### 13.6 怎么自己验一遍

```bash
# 看游戏装在哪、会往哪写文件
cargo run --bin peek -- game

# 拿一个本地 zip/pak 真装一次（会改游戏目录）
cargo run --bin peek -- install "D:/某个/mod.zip"

# 看某个 pak 里都有什么（排查用）
cargo run --bin peek -- ls "<游戏>\FSD\Content\Paks\mods_P.pak"
```

1. 装的时候，如果游戏目录里的同名 DLL 不是我们的，先复制一份到 `<数据目录>\game-backup\`；
2. 卸的时候，有备份就把备份复制回去，没备份且确认是我们的才删，游戏自带的那个绝不动。

判断「是不是我们的」按文件大小比对（我们内嵌的那份多大，`integrate::hook_dll_len()` 就说多长）。

## 16. 缓存与离线使用（已完成）

### 16.1 缓存放在哪

程序每次成功搜到一页、或者说拿到一个 mod 的详情，都会在数据目录里留一份：

| 存什么 | 文件位置 | 里面记了什么 |
|---|---|---|
| 一页搜索结果 | `<数据目录>\cache\search\<关键词>-<短哈希>-p<页码>.json` | 这一页的数据 + `cached_at`（抓取时刻，unix 毫秒） |
| 一个 mod 的详情 | `<数据目录>\cache\detail\<mod id>.json` | 详情 + `cached_at` |
| 已装列表 | 不另存，仍读 `mods\installed\<id>.json` 的记账 | 本来就存在本地，断网也读得到 |

关键词里的 `/`、`:`、空格会被换成 `_`；后面那串短哈希（FNV-1a）是为了让「钻石 矿」和「钻石-矿」不会落到同一个文件里。空关键词（看热门）存成 `热门-<哈希>-p1.json`。

文件里除了数据本身，还记着什么时候抓的——界面据此说「以下是 10 月 28 日 03:01 抓到的数据」。

### 16.2 什么时候用缓存

只有一种情况会翻缓存：**请求发不出去或连不上**（DNS 不通、被墙、本地加速工具没开）。

- 令牌无效（401）、被限速（429）、mod 不存在（404）**一律如实报错**，不用旧数据糊过去——否则用户会以为「登录正常、只是网慢」，实际是令牌过期了。
- 有缓存：返回上次的数据，并标 `stale: true` + 缓存时间；界面在结果上方显示一条黄色横条「当前离线，以下是 … 抓到的数据，可能已经过期」+「重试」按钮。
- 没缓存：照旧报「连不上 mod.io」，配错误卡片（§15.1）。

### 16.3 为什么用文件、不用数据库

用户拍板（2026-10-28）：先用 JSON 文件，**等以后升级迭代真需要了再换 SQLite**。理由：现在数据量就是一页 20 条 + 本地几个已装 mod，JSON 零依赖、出问题能直接打开看；真正需要 SQLite 的是后面读存档的看板。

为了让以后换起来不疼，所有读写都关在 `app\src-tauri\src\cache.rs` 一个文件里（`Cache::save_search` / `load_search` / `save_detail` / `load_detail`），外面只认这套接口，换实现时不动调用方。

### 16.4 怎么验的

命令行（`cargo run --bin peek -- search brighter`，`peek` 走的是和界面同一条命令，所以缓存与回退一并测到）：

| 场景 | 结果 |
|---|---|
| 联网搜 | 成功，写出 `cache\search\brighter-b2a2d196-p1.json` |
| 断网搜同一个词 | 打印「（这是离线缓存，抓取时间 …）」并列出同样的 7 条 |
| 断网搜没搜过的词 | 照样报「连不上 mod.io」，没有假装成功 |

真窗口（`node _tools/check-m4.mjs 离线` / `联网`）：

| 场景 | 界面表现 |
|---|---|
| 断网 + 有缓存 | 顶部黄条「当前离线，以下是 10 月 28 日 03:01 抓到的数据，可能已经过期。」+「重试」；下面照常列出 7 条 |
| 断网 + 背包 | 已装列表照常显示；点「卸载」成功，提示「卸掉了：离线测试用假记录。这是最后一个，已经清干净」 |
| 联网 | 黄条不出现（`bannerText: null`），列表照常 7 条 |

**怎么假装断网**：给进程设一个指向死端口的代理（`HTTPS_PROXY=http://127.0.0.1:9`），请求会在建立连接时被拒，错误类型正是「连不上」，因此走的就是和真断网同一条代码路径。这样不用动用户的加速工具、也不改系统网络设置。

**局限**：真去拔网线、或者关掉 `Steamcommunity_302` 的场景没有实测——两者在程序看来都是「连接失败」，但严格说只是等价推断，不是同一个现场。

### 16.5 还没做的

- 缓存不会自动清理，也不限制条数；用久了 `cache\search\` 会攒下很多小文件（每个几 KB）。要清就直接删这个目录，程序会重新攒。
- 缓存没有过期判定：一份三天前的数据，界面照样拿来用，只靠横条上的时间去提醒。

## 17. 不走 mod.io 的 mod、配置搬运、诊断信息（已完成）

### 17.1 能导入什么

「背包」页多了两个按钮：**导入本地 mod 文件**、**导入文件夹**。三种输入都认：

| 你选的 | 程序怎么做 |
|---|---|
| 一个 `.pak` | 直接复制到我们的目录，再合并进游戏 |
| 一个装着 `.pak` 的 `.zip` | 直接用（整合逻辑会自己把里面那个 pak 抽出来） |
| 一个解包后的文件夹，里面**只有一个** `.pak` | 用那个 pak |
| 一个解包后的文件夹，里面**没有** `.pak` | 把整个文件夹打成一个 pak 再用 |
| 一个解包后的文件夹，里面有**多个** `.pak` | 不猜，报错把名字列出来，让用户自己选 |

不管哪种，都会**复制一份到 `<数据目录>\mods\local\`** 再装。这样用户之后把原文件删了、挪走了，已经装进游戏的东西不受影响，卸载也还能找回记账。

界面上的文件选择用的是 Tauri 官方对话框插件（`tauri-plugin-dialog`）：网页里那个 `<input type=file>` 出于安全拿不到真实路径，装不了本地文件，所以必须走系统对话框。

### 17.2 本地 mod 的 id 怎么算

mod.io 给的 id 是它自己的数字；本地 mod 没有 id，就用「路径算哈希」当 id：同一个路径每次算出同一个值，**重复导入是覆盖同一条记录**，不会越攒越多。

两个约束：

- **不能跟 mod.io 的 id 撞**：mod.io 的 id 都在 10 位以内，所以本地 id 固定抬到 `2^52` 以上，两边永远分得开。
- **不能超过 `2^53`**：界面是 JS，数字一旦超过 `2^53` 就会丢精度，界面上的 id 和后端的对不上，点「卸载」就找不到那条记录。这个坑真的踩到了——第一版把最高位打开（`2^63` 那个量级），导入后界面上显示 `14150504100936321000`，后端记的是 `14150504100936321054`。改成 `2^52 ~ 2^53` 区间后，来回传的都是 `4697671365593118`，卸载正常。

### 17.3 配置文件里有什么、没有什么

「设置」页多了「配置搬运」：**导出配置**生成 `<数据目录>\config-<本机日期>.json`，**读一份配置来比对**只做比对、不自动安装。

```json
{
  "kind": "rock-sprout-config",
  "schema": 1,
  "exported_at": 1793128353396,
  "app_version": "0.1.0",
  "mods": [{ "name": "更亮的矿物 1.12.3", "source": "local", "url": null, "filename": "更亮的矿物 1.12.3-321054.zip" }],
  "settings": {}
}
```

- **没有令牌**，也永远不会有：文件里只有「装了哪些 mod」的名单。这一条有单测盯着（断言导出内容里不出现 token 字样），也有实测（拿真令牌前 20 个字符去 `grep -F` 检查，没命中）。
- `settings` 目前是空对象：v0.1 唯一的设置就是令牌，而令牌不导出。
- `schema` 是给以后升级用的：读到自己不认识的 `kind` 会说「这个文件不是岩笋的配置」，读到更高的 `schema` 会说「更新版本，请先升级」。
- 比对结果只报**差在哪**：配置里有、本机没有的；本机有、配置里没有的；两边都有的。同名但来源不同（一个 mod.io、一个本地）算两个不同的 mod。

### 17.4 诊断信息

「设置」页最下面「遇到问题？→ 复制诊断信息」把这几行整理好放进剪贴板（放不进去时同时显示在页面上，让用户自己选中复制）：

### 17.5 怎么验的

命令行（`peek import` / `peek clear` / `peek export-config` / `peek import-config`，走的是和界面同一条命令）：

| 场景 | 结果 |

| 原样读回来 | 「两边一致，都是 1 个 mod。（导出这份配置的程序版本 0.1.0）」 |

真窗口（CDP 驱动，`_tools\check-m5*.mjs`）：

| 场景 | 结果 |
|---|---|
| 背包页按钮 | 刷新 / 导入本地 mod 文件 / 导入文件夹 |
| 导入后列表 | 出现「更亮的矿物 1.12.3」，记账里 `source: local` |
| 点「卸载」 | 「卸掉了：更亮的矿物 1.12.3。这是最后一个，已经清干净」；游戏目录合并包消失、DLL 回到 386,560 字节（日志有「已把加载器换回游戏自带的 DLL」） |
| 设置页按钮 | 导出配置 → `config-20261028.json`（1 个 mod）；读回来 → 「两边一致，都是 1 个 mod」 |
| 诊断信息 | 生成 10 行，含游戏路径与三种 DLL 状态；窗口没在前台时剪贴板拿不到，界面改说「已经生成在下面，选中复制就行」 |

**断网验收**（真窗口 + `HTTPS_PROXY=http://127.0.0.1:9` 假装断网，`_tools\check-m5-offline.mjs`）：

| 动作 | 断网时 |
|---|---|
| 搜索 | 报「连不上 mod.io（… os error 10061）」，如实失败 |
| 导入本地 mod | **成功**，合并进游戏 |
| 已装列表 | 照常显示（1 个，来源 local） |
| 导出配置 / 读回来 | **成功**，「两边一致，都是 1 个 mod」 |
| 卸载 | **成功**，合并包删掉、DLL 换回原版 |

也就是说：**除了「搜」和「下载」必须联网，其余都能在断网状态下做完**——这正是 M4+M5 合起来想要的效果。

**局限**：系统文件对话框是原生窗口，脚本点不了，所以验收里「导入」是直接调后端那条命令（`import_local`），走的仍是界面用的同一套调用；「点了按钮弹出对话框、选完文件」这一段是由用户在真机上试的。

### 17.6 这次踩到的两个坑

1. **`u64` 的 id 传进 JS 会丢精度**（见 §17.2）。教训：凡是给界面的数字，都要问一句「会不会超过 `2^53`」。
2. **卸载时不能「没备份就删」那个 DLL**。第一版 `clear()` 是「有备份就还原，没备份且确认是我们的就删」。测试时我把整个数据目录删了重建，备份随之消失，卸载走的就是「删掉」那条路——游戏目录里那个 `x3daudio1_7.dll` 直接不见了（它是游戏自带的音频库，我们的加载器只是借名字做转发）。现在改成：**没有备份就一个字节都不碰**，只记一条警告（下次装 mod 时会自动备份）。宁可把加载器留着（游戏照常启动），也不凭空删游戏目录里的文件。

### 17.7 还没做的

- 导入时不会去 mod.io 查「这是哪个 mod」，所以本地 mod 在列表里没有简介、没有封面、没有版本号。
- 配置比对只告诉差在哪，不会一键「把你缺的都装上」。
- 本地 mod 的记账不记录原始路径，只有文件名——换个路径导入会被当成两个 mod（id 按传入路径算）。
