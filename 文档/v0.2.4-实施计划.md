# v0.2.4 实施计划 · 天赋面板

> **依据**：`文档/路线图-v0.1到v1.0.md` §4「v0.2.4 · 天赋」
> **这一版的目标**：让玩家一眼看到「我买了哪些天赋、各到几级、一共花了多少星点、还剩多少」。全程只读。

---

## 0 · 已定决策

| # | 决策 | 取舍理由 |
|---|---|---|
| 1 | **新建独立的「天赋」页**，位置在「我的数据」和「装备」之间 | 这页有两个正交维度（已买清单 × 每角色带什么），塞进「我的数据」会撑成大杂烩 |
| 2 | **全量 24 条 + 未买灰显** | 这页的价值是「我还能买什么」；只列已买会退化成装饰性清单 |
| 3 | **显示三个数：已赚 / 已花 / 还剩** | 剩余直接读存档 `PerkPoints`；已赚与已花各自独立推算，见 §2 |
| 4 | **硬校验：已赚 − 已花必须等于存档的 `PerkPoints`** | 对不上说明某张表抽错，宁可不显示也不报错数 |
| 5 | **校验失败时天赋清单照常显示**，只有点数区写「点数对不上，先不显示」 | 一个坏掉的校验不该把还能用的东西一起藏起来 |
| 6 | **中文名走人工 24 条表**，每条必须带出处 | locres 键→值映射在 v0.2.2 卡过两天；24 条是人工可控规模，宁慢不错 |
| 7 | **只显示「已买 / 未买」，不解释为什么买不了** | Tier 门槛规则来自 wiki、不在资产里，说错比不说更糟 |
| 8 | **每角色显示「当前生效」的那套天赋**（`RandomEquippedPerkLoadout`） | 用户问的是「这个角色现在带什么」，不是历史预设 |
| 9 | **排序：已买在前（按 rank 降序），未买在后（按 Tier、花费升序）** | 先回答「我有什么」，再回答「下一个买得起的」 |
| 10 | **这版不做天赋描述** | 描述里带 `{value}` 占位符要按 rank 填值，是另一套逻辑 |
| 11 | **只读红线不变**：不写存档、不碰游戏目录、不动 25+ 命令签名 | 全程只读是本项目的基础承诺 |

## 2 · 数据契约

### 2.1 新增两份数据（`app/src/data/`）

**`perk-names.json`**（人工整理，24 条）

```json
{
  "$comment": "天赋名。中文名为人工整理，每条必须在 source 里写出处。",
  "$source": "资产名取自 FSD/Content/GameElements/KPI/Perks/PERK_*.uasset",
  "perks": [
    { "asset": "PERK_Vampire", "guid": "f747e1d81bba744980e385e8610d11a6",
      "en": "Vampire", "zh": "吸血鬼", "source": "游戏内天赋页截图" }
  ]
}
```

- `guid` 必须是小写 32 位 hex，与存档 `PerkID` 逐字相同。
- `source` 只接受「游戏内截图」或「官方 wiki 原文」两种出处，不接受「印象」。
- 抽不到的填 `zh: null`，界面显示英文名，不猜。

**`perk-costs.json`**（从资产抽，24 条）

```json
{
  "$source": "从 24 个 PERK_* 资产按 Ranks[] 逐级读出，读法见 §2.2",
  "perks": [
    { "guid": "f747e1d81bba744980e385e8610d11a6", "asset": "PERK_Vampire",
      "ranks": [ { "tier": 6, "cost": 2 }, { "tier": 7, "cost": 3 },
                 { "tier": 8, "cost": 5 }, { "tier": 9, "cost": 7 } ] }
  ]
}
```

- `PERK_PerkSlots_Active` 没有 Ranks（靠晋升解锁），`ranks: []`。
- `PERK_PerkSlots_Passive` 的两级花费是 15 / 20，不是 2/3/5/7 那一套，不要套模板。

### 2.2 三个数怎么算

```
已赚 = Σ 对每条 ClaimedKPIRewards：
         sum( milestone.tiers[0 .. Tier-1].perkPoints )
已花 = Σ 对每条 OwnedPerks：
         sum( perk.ranks[0 .. currentRank-1].cost )
还剩 = SaveData.PerkPoints        ← 直接读，不参与上面的加总
校验 = (已赚 - 已花 == 还剩)
```

**校验不通过时**：三个数一个都不显示，点数区写「点数对不上，先不显示」；清单照常渲染。

这条校验是 `Ranks` 读法的唯一证明手段——`Ranks` 的字节对齐没有上游文档，只有让两个独立来源对上，才能说读对了。

### 2.3 后端命令

新增一个只读命令 `get_perks`，返回：

```ts
{
  points: { earned: number | null, spent: number | null, left: number, verified: boolean },
  owned: { guid: string, rank: number, name: { en: string, zh: string | null }, ranks: {tier:number,cost:number}[] }[],
  all:   { guid: string, name: {...}, ranks: [...], ownedRank: number | null }[],   // 24 条，ownedRank 为 null 表示未买
  loadouts: { characterId: string, perkGuids: string[] }[]
}
```

- `verified === false` 时 `earned` / `spent` 为 `null`。
- 空档、读不通、版本不认识三种失败态沿用现有 `MyData` 的三句文案。

## 3 · 里程碑

### M0 · 数据落地（先做，不动界面）

- 抽 24 个资产的 `SaveGameID` / `Ranks[]`（`Tier` + `Cost`）→ `perk-costs.json`
- 人工整理 `perk-names.json` 24 条 + 出处
- **报三个数**：资产 24 / 读到 Ranks 的 N / 名字表 24 条里中文齐的 M
- 若 Ranks 读出的级数与存档 rank 分布明显不符（例如某天赋 currentRank=4 但 Ranks 只有 2 级），**停下来报数**，不要自行猜读法

### M1 · 点数算法 + 交叉校验（纯后端 + 单测）

- 实现 §2.2 三式与校验
- 单测至少覆盖：已领 0 条、已买 0 条、`Tier=0` 的元素（既有回归里已有这条纪律）、已赚−已花 不等于存档值的场景（必须返回 `verified: false`）
- **验收**：本档算出 `已赚 − 已花 = 35`，且三个数都非空

### M2 · 后端命令 + 契约

- `get_perks` 与前端类型；空档 / 读不通 / 版本不认识三态
- 不做界面也要能通过命令拿到完整 JSON

### M3 · 「天赋」页

- 导航位置：「我的数据」和「装备」之间
- 顶部点数区：已赚 / 已花 / 还剩；`verified=false` 时只显示「点数对不上，先不显示」
- 天赋清单：已买在前（rank 降序），未买灰显在后（Tier、花费升序）；每条显示名字、当前等级 / 满级、总花费
- 页底一段「每个角色当前带的」：角色标识（认不出职业就写「角色 N」）+ 那 4–5 个天赋名
- 不显示：描述、Tier 门槛解释、历史预设栏位

### M4 · 回归与出包

- 新增回归场景：天赋页可打开、点数三个数存在且自洽、未买条目灰显且不可点、角色段有内容、`verified=false` 分支（用构造数据）
- 版本号四处改 0.2.4；门禁默认跑法全过
- 发布说明三句如实写，已知限制：中文名人工整理、`Ranks` 读法无上游文档佐证（靠交叉校验证明）

## 4 · 验收（能演示的）

1. 打开天赋页，看到 21 条已买（按 rank 从高到低）和 3 条未买（灰）。
2. 点数区显示三个数，且已赚 − 已花 = 35。
3. 页底能看到 4 个角色各自带的天赋。
4. 构造一份「已赚−已花 ≠ 存档值」的数据，点数区变成「点数对不上，先不显示」，清单还在。
5. 拔掉 `perk-costs.json` 的某一条，界面降级为不显示已花与剩余，不崩。

## 5 · 这版不做

- 天赋描述（`PerkDescriptions` 68 条，含 `{value}` 占位符）
- Tier 门槛规则与「为什么买不了」
- `EquippedPerkLoadouts` 的 6 个预设栏位
- 任何写操作（重置天赋、修改等级）
- 喷漆（8.1% 数据密度，推迟，未定版本）

## 6 · 风险

| 风险 | 触发条件 | 应对 |
|---|---|---|
| `Ranks` 读错 | 交叉校验不通过 | 不显示已赚/已花，只显示还剩；报差异表 |
| 中文名查不到 | 某条天赋在游戏内没有中文 | 该条显示英文名，不猜 |
| 角色认不出职业 | `CharacterClass = None`（既有问题） | 显示「角色 N」，不猜 |
| 点数对不上是数据本身的问题 | 存档被改过 | 同上，降级显示，不报警为「程序错误」 |
