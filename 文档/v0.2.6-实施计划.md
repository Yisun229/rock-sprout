## §3 里程碑

### M0 · 数据与名字（先做，后面都依赖它）

1. **四种酿造料中文名**：走既有 locres 链路取，值落 `names.json` 的 `zh` 字段；取不到就**保留英文并在界面注明**，不许硬译
2. **酒单**（先解包）：
   - 在 pak 里找酒吧相关资产（酒品定义 / 配方）。找到就抽「酒名 + 需要哪几种料 + 各要多少」
   - 抽不到 → 退回人工表 `app/src/data/beers.json`，字段 `{ id, en, zh, needs: [{id, count}] }`
   - **两种来源都必须写 `$source`**，写明是资产抽的还是人工建的
3. **验收**：`beers.json` 里每条的酒名非空、`needs` 至少一项；四种料的中文名与英文名都能取到

### M1 · 商店取数（后端）

1. 新写 `app/src-tauri/src/store.rs`：
   - `fetch_price(appid, cc) -> { currency, initial, final, discount_percent }`
   - `fetch_players(appid) -> u64`
   - 接口：`https://store.steampowered.com/api/appdetails?appids={appid}&cc={cc}&l=schinese` 与 `https://api.steampowered.com/ISteamUserStats/GetNumberOfCurrentPlayers/v1/?appid={appid}`，**都不需要 key**
2. 国家代码从设置读，默认 `CN`；`settings.rs` 加一个字段，设置页加一个输入框
3. 超时 15 秒、失败返回 `Err(String)` 人话，**不重试**（这是展示性数据，失败就显示缓存）
4. 缓存：结果落 `data/cache/steam.json`，带 `fetched_at`；断网时用缓存并显示「X 分钟前拿到的」
5. **验收**：`cargo test` 覆盖「正常回包解析」「回包里 `success:false`」「网络错误不 panic」；命令行能跑出一次真实价格

### M2 · 商店块（前端，并进今天页）

1. 位置：「今天」页「官方公告」之后、「新冒出来的 mod」之前
2. 内容一行一列：游戏价 · 折扣 · 在线人数 · 拿到时间；DLC 有价就列一行
3. 三种状态与「今天」页其余块一致：骨架 → 有数据 → 「这块没取到」+ 重试
4. **验收**：断网截图（用缓存）、正常截图、无折扣时截图，三张

### M3 · 酒吧块（前端，并进今天页）

1. 顶部：四种酿造料各多少个
2. 列表：每条酒一行，右侧标「能点」或「还差 N 个 X」；料够的排前面
3. 缺料时只做颜色区分，不加图标、不弹窗
4. **验收**：料全够、部分够、全不够三种状态截图；至少一条「还差 N 个」的文案与实际数量对得上

## §5 风险与未知

1. **酒单可能抽不到**——若 pak 里没有酒品定义，退回人工表，`$source` 必须写明
2. **Steam 接口可能被地区限制**——CN 区价格若返回空，就在设置里改区，界面写清当前用的哪个区
3. **8 条补充里有 3 条分母可能拿不到**（E3 服装等级、D7 无人机皮肤）：拿不到就只显示已有的数，不造分母
4. **`--with-stock` 会动游戏目录**：跑前必须确认 `_tools/backup-ue4ss/` 与当前目录逐字节一致，还原以跑前实时快照为准
