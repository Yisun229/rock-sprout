## 0. 已定决策（开工后不再重新讨论）

| 决策 | 结论 | 原因 |
|---|---|---|
| 代码来源 | 从 `trumank/mint` 起分支重写，**不复制 MintCat 代码** | MintCat 仓库无许可证 = 默认保留所有权利 |
| 界面 | 必须与 MintCat 明显不同 | 布局、配色、控件排布、交互时序都受著作权保护 |
| MintCat 的 patch | 只当**设计笔记**看，逻辑重敲一遍，不原样粘贴 | patch 的上下文行仍是它的代码 |
| mod.io 鉴权 | 用户粘贴**个人访问令牌**；粘贴后立刻调 `/me` 取真实 uid | 不需要 OAuth 回调、不需要服务器 |
| 列表数据 | 只走 mod.io API，不做镜像清单 | 全量快照的维护成本撑不住 |
| 云备份 | 砍掉，改**导出 / 导入 JSON** | 不碰用户数据 = 没有保管与泄露责任 |
| UE4SS | v0.1 不做 | 全在前端且与装 mod 主线无关 |
| 国内网络 | 不解决，README 明示"需要能访问 mod.io" | 只服务自有用户群 |
| 收费 | 完全免费 | 长期非商业，不设付费墙 |
| 产品名 | **岩笋 · Rock Sprout** | 已定版；`SUNSHOOT` 弃用（地下世界没有太阳，且英文名需与中文对应） |
| 品类名 | 深岩银河伴侣 / DRG Companion | 不用"启动器"（承诺过重 + 盗版联想） |
| 底座策略 | **底层尽量拿，界面一点不拿，品牌全部自己做** | 底层用 `mint_lib`（MIT 明确授权）；界面、命令层、品牌全部自写 |
| 工作区根目录 | **`E:\岩笋 · Rock Sprout`** | 文档、源码、工具链、依赖全部落在这里，不再往 C/D 盘新增 |

## 1. 技术栈建议

| 层 | 选型 | 备注 |
|---|---|---|
| 外壳 | Tauri 2 | 保住你的 React / AntD 经验 |
| 前端 | React 19 + TypeScript + Vite | 重新写，不沿用 MintCat 的 src |
| 后端 | Rust，薄 command 层 + `mint_lib` | pak 合并 / mod.io 下载复用 mint |
| 存储 | 本地 SQLite | 已装列表、搜索缓存、设置 |
| 凭据 | Windows 凭据管理器（`keyring` crate） | 令牌不进配置文件 |
| 打包 | `cargo tauri build` → NSIS | 单 exe 安装包 |

> **备选方案**：全部留在 `egui` 里写（工作量小一些，但 UI 全靠手搓，前端经验用不上）。
> **开工第一件事就是定这个分叉。**

### M2 · mod.io 客户端（约 1 周，核心）

> 先跑通 §5 的三条 curl，再写代码。

- [x] 令牌存在数据目录的 `modio-token.txt` 里（明文单行文件；`keyring` 那套没采用，理由见《v0.1-实施计划》§12）
- [x] 存令牌时立刻调 `GET https://api.mod.io/v1/me` 验证，并取出 `id` 当 uid 显示
- [x] 之后所有请求都带到 `https://api.mod.io/v1`，头 `Authorization: Bearer <token>`（**没用 `u-{uid}.modapi.io`，令牌本身就是身份**）
- [x] 搜索：`/v1/games/2475/mods?_q={q}&_sort=-downloads_total`（mod.io 的搜索参数是 `_q`，不是 `name`）
- [x] 详情：`/v1/games/2475/mods/{mod_id}`
- [x] 文件列表：`/v1/games/2475/mods/{mod_id}/files?_sort=-date_added`
- [x] 下载：拿 `binary_url` 后由 Rust 流式写盘（前端只传 mod id）
- [x] 429 退避（`Retry-After` 优先，缺省 5 秒、上限 60，自动重试一次）
- [x] **不要写死 uid**（这是 MintCat 的坑：所有人都挤在 `u-13595141`）

**验收**：命令行里能完成：验证令牌 → 搜到 mod → 拿到下载地址 → 下载成功。

## 3. v0.1 完成的定义（六条全过）

在一台干净的 Windows 上：

1. 装好 → 粘令牌 → 搜到 mod → 点安装 → 进游戏生效 —— **已通**（真机验过，见《v0.1-实施计划》§14）
2. 卸载 → 游戏恢复原样，无残留 —— **已通**（卸载后 `mods_P.pak` 消失、原版 DLL 换回）
3. 令牌填错 → 明确提示 + 一键直达修复页 —— **已通**（错误卡片有「去设置页」按钮）
4. 断网 → 显示缓存 + 明确离线提示 —— **没做**（缓存与离线启动在 M4）
5. 导出配置 → 另一台机器导入 → 列表还在 —— **没做**（M5）
6. 点"报告问题" → 复制出诊断文本 —— **没做**（诊断信息还只在日志文件里）

## 5. 开工前先做的三条 curl（10 分钟，消掉所有假设）

令牌获取：登录 mod.io → <https://mod.io/me/access> → 生成 → 复制

```bash
TOKEN="粘贴到这里"
UID="<从第 1 条返回的 id>"

# 1. 令牌是否有效，以及你的 uid
curl -H "Authorization: Bearer $TOKEN" https://api.mod.io/v1/me

# 2. 能否读 DRG 的 mod 列表
curl -H "Authorization: Bearer $TOKEN" \
  "https://u-$UID.modapi.io/v1/games/2475/mods?limit=5"

# 3. 下载地址长什么样（看是 302 还是 JSON 里的 binary_url）
curl -i -H "Authorization: Bearer $TOKEN" \
  "https://u-$UID.modapi.io/v1/games/2475/mods/<MOD_ID>/files/<FILE_ID>/download"
```

**三条都通了，剩下的就是纯写代码。**

## 9. 预留接口（v0.1 内完成，每个不到一天）

> 原则：**预留边界，不预留实现。** 判据只有一条——这个缝现在不留，以后要改几处？
> 只改 1 处 → 不留（以后改一下就行）；会改 3 处以上 → 现在留（否则要翻整个项目）。

| # | 预留什么 | 具体做法 | 成本 | 解锁到 |
|---|---|---|---|---|
| 1 | 路径入口 | 所有落盘走同一个 `Paths`，任何地方不写死路径 | 半天 | v0.4 便携 / v1.1 读存档 |
| 2 | 导航分组 | 导航分两组 `mods` / `companion`；后者为空时不显示 | 1 小时 | v1.2–v1.6 六个面板 |
| 3 | mod 源接口 | 抽 `ModSource`（search / detail / files / download），v0.1 只有 mod.io 一个实现 | 1 小时 | 以后的本地库、镜像 |
| 4 | 存档探针 | 空模块 `save`，只留 `probe() -> None`；UI 侧留一块"数据为空就整块不渲染"的区域 | 半小时 | v1.1 起全部面板 |
| 5 | 文案外置 | 所有界面文字提到一个文件，不散落在组件里 | 1 小时 | 面板变多后不失控 |
| 6 | 主题 token | 颜色 / 间距 / 圆角写成一套变量，v0.1 不做视觉设计 | 1 小时 | v0.5 一次性上色 |

**明确不预留的**：

- 事件总线 / 状态订阅（现在没人需要，以后面板要刷新时再加）
- 多语言框架（先只放中文，真有两套语言时再说）
- 数据库迁移框架（v0.1 一张表，等真有第二版结构再补）
- 插件系统（没有第三方要接，不做）

**为什么这六条值得现在留**：它们全部是"改动会扩散到全项目"的位置。`Paths` 晚了要翻遍每个 `PathBuf`；导航晚了要重排所有路由；`ModSource` 晚了每个调用点都要改。而它们现在每个都只要几十分钟，且不影响 v0.1 的功能范围——只是让 v0.1 的形状是"能长出去"的，而不是"封死的"。
