## 1. 这一版要解决什么

「我的数据 / 天赋 / 装备」三页解决的是**资产**，「本周」解决的是**节奏**——玩家打开它，想知道「这周我还能打什么、还剩多少没拿」。

三块数据的真实状况（只读调查已确认）：

- **赛季**：18 个字段全在，XP / 奖励领取 / 节点 / 挑战都在；但**没有赛季序号**，只有 `SeasonID` GUID；奖励数组**只有下标没有 ID**。
- **深潜**：有 `DeepDiveSave`，但字段集合不固定（33 档里 4 种形状）；普通档常常只有「完成过」一个布尔；**没有周次、没有关卡名**（游戏按种子生成，pak 里根本没有本周内容）。
- **战役**：`UnLockedMissions` 7 条、`UnLockedPlanetZones` 3 条、`UnLockedMissionParameters` 6 条、`CompletedCampaigns` 15 条，全是裸 GUID；**没有完成标记**。

所以这一版真正的工作量不在界面，在**把 GUID 变成名字**。

## 2. 名字链（M0，本版最大的一块）

### 2.1 为什么必须解 pak

只读调查已实测：存档里的五类 GUID 拿去和 61 个 locres 命名空间比对，**命中 0**。它们不是 FText 键，是资产的 `SaveGameID`。必须走「解包资产 → 读 `SaveGameID` → 读资产里的名字字段 / FText 键 → join locres」这条链。这条路 v0.2.3 已经踩熟（`upgrades.json` / `perk-names.json` 都是这么来的）。

### 2.2 要解的五类资产

| 类别 | pak 路径 | 数量 | 存档里的字段 |
|---|---|---|---|
| 任务类型 | `FSD/Content/GameElements/Activities/Missions/ACT_*.uasset` | 11 | `UnLockedMissions`（7 条） |
| 区域 | `FSD/Content/GameElements/Missions/PlanetZones/PZ_Zone0*.uasset` | 4 | `UnLockedPlanetZones`（3 条） |
| 赛季 | `FSD/Content/GameElements/Seasons/Season0X/Season_0X.uasset` | 7 | `SeasonSave.Seasons` 的键（2 条） |
| 赛季挑战 | `FSD/Content/GameElements/Seasons/SeasonChallenge_*.uasset` | 14 | `ActiveChallenges[].ChallengeGuid`（3 条） |
| 战役 | `FSD/Content/GameElements/Campaign/CP_*.uasset` | 59 | `CompletedCampaigns`（15 条） |

**产物**：五张表放 `app/src/data/`，每张带 `$source` 写明「pak 路径 + 从哪个字段读出 + locres 命名空间」。格式参照 `perk-names.json`：

```json
{ "$source": "…", "items": [ { "id": "32位小写hex", "en": "…", "zh": "…", "asset": "ACT_…" } ] }
```

### 2.3 三条必须遵守的规矩（都是踩过的坑）

1. **表的口径由资产全集决定**，不许从「某一份存档里出现过的 GUID」反推（v0.2.4 的 Driller 漏行就是这么来的）。
2. **查表不能假定命名空间**：全命名空间建索引，同名键多值时**比对值**，值不一致记冲突并打印，该条留英文（v0.2.3-M1 §6）。
3. **喂工具的清单文件一律 UTF-8 无 BOM**（踩过两次；BOM 会让第一条静默查不到）。

### 2.4 验收

- 95 个资产**逐个**报「解出 N / 有 SaveGameID N / 配上名字 N」，三个数字必须相等；有任何一条不等就报出来，不许凑。
- 拿主档实测：任务 7/7、区域 3/3、赛季 2/2、挑战 3/3、战役 15/15 全部配出中文名。
- 表里每一条的 `en` 与 `zh` 都要非空；只有一边有值时如实标，不许留空字符串冒充。

## 3. 赛季块

### 3.1 赛季等级（M1）

解 `FSD/Content/GameElements/Seasons/Curve_XPToPerformancePoints.uasset`，读出 XP→赛季等级的分段曲线，存 `app/src/data/season-levels.json`。

- 曲线是**资产里的数值**，不是社区表，`$source` 要写清。
- 等级上限以曲线为准；超出上限时显示「已满级」。
- 验收：拿主档两个赛季的 XP（247075 / 74640）各算出一个等级，并写明这两个数落在曲线的哪一段。

### 3.2 赛季奖励（M1，带对齐关卡）

`RewardsClaimed` 是 70 条的 `{NormalClaimed, SpecialClaimed}`，**下标即槽位序**。奖励清单在 `Season0X/TreeOfVanity_Season*.uasset`。

**做法**：先解 `Season_00.uasset`，把奖励树的有序列表打出来，**数出节点数**：

- 若节点数 = 70（与 `RewardsClaimed` 长度一致）→ 按下标显示每项名字与领取状态；
- 若不等于 70 → **不许硬对**，继续查这 70 个下标对应的到底是什么（可能是「等级 1–70 的奖励槽」而树是另一套编号），查清为止。

验收：主档显示「已领 46 / 共 70」，逐项名字来自 locres 且中英文都对得上；**如果最终确认无法对齐，必须在发布说明里明写「奖励名对不齐，只给数量」**——这是最后手段，不是第一选择。

### 3.3 本周挑战（主角）

`ActiveChallenges` 3 条，每条有 `CurrentWins` / `NumberOfWins` / `XPCompleteGain` / `TokenGain`。

- 显示：挑战名（`ChallengeGuid` 进挑战表）+ 进度 `X / Y` + 完成给多少 XP/代币。
- 进度条只在 `NumberOfWins > 0` 时画，避免除零。
- 已完成的挑战（`CurrentWins >= NumberOfWins`）标「已完成」。

### 3.4 刷新时间（M5）

存档里没有刷新时刻，`ActiveCampaignWeek` 是哈希周号，`LastNewChallengeGiven` 是「上次发挑战」。所以只能写死游戏规则。

- 先查证**确切 UTC 时刻与星期**，写进 `app/src/data/weekly-reset.json`：`{ "weekday": 4, "utcHour": ?, "source": ["…"] }`
- 界面上显示「下次刷新：X 月 X 日（周 N）」，**不显示倒计时**——倒计时每秒重算，为一个静态规则付这个代价不值。
- **查不到权威结论就不写具体时刻**，只写「每周四刷新」。写错一个钟点比不写更糟。

## 4. 深潜块

`DeepDiveSave { NormalSave, EliteSave }`，字段集合不固定，**缺字段是常态不是坏档**。

- 普通：有 `HasEverCompleted` 就写「完成过 / 没完成过」；有 `Progress` 就写「打到第 N 关」。
- 精英：同上。
- 有 `BestTime` 时显示「最好成绩 X 分 Y 秒」（秒为单位，超过 1 小时显示小时）。
- 有 `Rewards` 时显示条数。
- 顶部一句话：**「深潜每关的内容由游戏按种子生成，存档里只有种子，读不到关卡名」**——这句是解释，不是道歉。
- 不显示 `bHasOpenedDeepDiveTerminal`（工具无意义）。

## 5. 战役块

- **已完成的战役**：`CompletedCampaigns` 15 条 → 走战役表配名字，列表显示。
- **已解锁的任务类型**：`UnLockedMissions` 7 条 → 任务表配名字。
- **已解锁的区域**：`UnLockedPlanetZones` 3 条 → 区域表配名字。
- **解锁的任务参数**：`UnLockedMissionParameters` 6 条，值是复杂度和时长的 GUID 集合 → 暂不展开成名字，只显示「已解锁 N 类难度」这类汇总；这条写进「不做」。
- 不显示「还缺哪些」——我们没有完整任务总表，说缺口就是谎报。

## 6. 页面结构

```
本周
├─ 赛季（默认展开）
│   ├─ 一句话：第 ? 赛季 · 等级 N · 本周挑战 2/3 完成
│   ├─ 本周挑战（3 条，进度 X/Y）
│   ├─ 奖励：已领 46 / 共 70
│   └─ 下次刷新：X 月 X 日（周四）
├─ 深潜（默认收起）
│   ├─ 一句话：普通 完成过 · 精英 打到第 2 关
│   └─ 每个档：状态 + 最好成绩 + 奖励数
└─ 战役（默认收起）
    ├─ 一句话：已完成 15 个战役 · 解锁 7 种任务 · 3 个区域
    └─ 三组清单
```

- 页面顶部沿用「我的数据」的存档选择器（多份存档才出现下拉，一份就一行静态）。
- 三块都用现有 `.card` 样式，不新造组件。

## 7. 后端

新增一个命令 `progress_view(selected: Option<String>) -> ApiResult<ProgressView>`，按现有模式动五个文件（`ipc/progress.rs` 新建、`ipc/mod.rs`、`lib.rs`、`api.ts`、新页面）。

**必须改 `model.rs`**：现在 `SeasonEntry` 只留 8 个字段，`RewardsClaimed` / `NodesBought` / `ActiveChallenges` 只存 `.len()`，挑战明细和奖励明细全部丢失。要补：

- `SeasonEntry` 增加 `Rewards: Vec<RewardClaim>`（`normal` / `special` 两个布尔）、`ActiveChallenges: Vec<ChallengeEntry>`（`challenge_id` / `wins` / `total` / `xp` / `tokens`）、`NodesBought: i32`（保留数字）
- `DeepDiveItem` 增加 `BestTime: Option<i32>`
- `CampaignEntry` 增加 `Completed: Vec<Guid>`（已有）、任务/区域/参数三组原样保留

**改 `model.rs` 必须把 `store.rs` 的 `CACHE_VERSION` 从 3 加到 4**——模型变了缓存不变会一直读到旧结果（这个坑踩过两次）。

## 9. 明确不做

- 不显示「还缺哪些任务/区域/战役」（没有完整总表，说缺口就是谎报）
- 不显示赛季奖励的图标（pak 里有资产但工作量与收益不成比例）
- 不显示 `UnLockedMissionParameters` 里复杂度和时长的名字（只给汇总数）
- 不做倒计时（静态规则配不上每秒重算）
- 不解释深潜关卡内容（游戏按种子生成，我们没有）
- 不动 `model.rs` 以外的既有解析行为（只加字段，不改读法）

## 10. 风险

- **奖励下标对不齐**：这是本版唯一可能退坡的地方。缓解：先数节点数再动手，对不齐就查，不许硬对。
- **战役 59 个资产里有重名**（`CP_Weekly_1` 这类），locres 里可能多条命中同一个 FText 键 → 按规矩比对值，冲突的留英文并打印。
- **`Curve_XPToPerformancePoints` 可能是非线性分段**（每级不同增长）→ 不要假设等差，按资产里的实际点插值。
- **刷新时刻查不到权威结论**：已定「宁可不写具体时刻」。
