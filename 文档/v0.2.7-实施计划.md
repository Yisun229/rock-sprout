## §2 数据契约

### 2.1 Steam 五个接口，实测结论（2026-11-10）

**五个接口全部需要 key**（不带 key 时四个返回 `400 Required parameter 'key' is missing`，`GetOwnedGames` 返回 `401`）。这条推翻了"`GetSchemaForGame` 是公开元数据、无 key 也能调"的说法——实测它同样要 key。

| 接口 | 用途 | 关键特征 |
|---|---|---|
| `ISteamUser/GetFriendList/v1` | 好友 steamid 列表 | 只要 key + steamid；不含昵称头像 |
| `ISteamUser/GetPlayerSummaries/v2` | 昵称/头像/可见性 | **一次最多 100 个**；`communityvisibilitystate` 1=私密 2=仅好友 3=公开 |
| `IPlayerService/GetOwnedGames/v1` | 是否拥有 + 时长 | **不支持批量**，一人一次；时长单位**分钟**；`appids_filter=548430` 只取 DRG |
| `ISteamUserStats/GetSchemaForGame/v2` | 成就定义 | 本版不用 |
| `ISteamUserStats/GetUserStatsForGame/v2` | 个人成就 | 本版不用 |

**隐藏时的行为（必须当成契约写死）**：`GetOwnedGames` 在对方「游戏详情」不公开时返回 **HTTP 200 + `{"response":{}}`**，不是报错。解析必须按「空对象 = 不可见」处理，**不能当成"零游戏"**——否则好友会被显示成"没玩过任何游戏"。

### 2.2 设置新增字段（`app/src-tauri/src/settings.rs:12-23`）

```rust
pub struct Settings {
    // 既有三项不动
    #[serde(default)] pub steam_key: String,   // 32 位十六进制；空串=没配
    #[serde(default)] pub steam_id: String,    // 17 位数字；空串=没认出来
}
```

`ipc/translate.rs:80-83` 的 `get_translate_settings` 原样返回整个 `Settings`，所以新字段**自动**下发前端，不需要新命令。新增一条写入命令：

```
set_steam(key: Option<String>, id: Option<String>) -> ApiResult<SteamStatus>
```

`SteamStatus { has_key: bool, steam_id: String, source: "client"|"manual"|"none" }`

**存储方式**：`steam_key` 走与 mod.io 令牌同一套加密（`secret.rs` 的 DPAPI `seal`，落到 `<数据目录>/steam-key.sealed`），**不放进 `settings.json` 明文**。`steam_id` 是公开标识，可以明文放 `settings.json`。

### 2.3 缓存（`<数据目录>/cache/steam-friends.json`）

```json
{ "steamId": "7656119…", "fetchedAt": 1762…, "friends": [
  { "steamId": "7656119…", "name": "…", "avatar": "https://…",
    "visibility": 3, "ownsGame": true, "playtimeMin": 12345 } ] }
```

- 键必须含 `steamId`：换了 key 或换了账号，不能拿到上一个人的列表（v0.2.6 商店地区缓存没隔离踩过）
- 缓存里**不存 key**
- 10 分钟内不做请求，页面顶部显示"数据取自 HH:MM"

### 2.4 我的 SteamID 来源

按顺序试，命中即停：

1. 注册表 `HKCU\Software\Valve\Steam\ActiveProcess\ActiveUser`（DWORD，SteamID64 的低 32 位）→ 拼接成 64 位
2. `loginusers.vdf` 里 `MostRecent = 1` 那一段的键名（就是 64 位 ID）
3. 都失败 → 让用户贴主页链接，从 `steamcommunity.com/profiles/<数字>` 直接取；`/id/<自定义名>` 走 `ResolveVanityURL`

前两步读不到就**什么都不显示**，不报错。

### M1 · 好友页数据层

新增 `app/src-tauri/src/friends.rs`：

```
fn my_steam_id() -> Option<String>            // §2.4 的三级回退
async fn friends_of(id, key) -> Vec<String>    // GetFriendList
async fn summaries(ids, key) -> Vec<Summary>   // 分批，100/批
async fn owns(steamid, key) -> Option<Owns>    // 单次；空对象 → None
```

命令：

```
get_friends(force: bool) -> ApiResult<FriendsView>
  FriendsView {
    state: "ok" | "no_key" | "no_id" | "bad_key" | "offline",
    fetched_at: Option<u64>,
    from_cache: bool,
    visible: Vec<FriendRow>,      // 公开且查过的
    hidden_count: u32,            // 可见性 != 3 的
    checked: u32, total: u32      // 进度
  }
```

**请求序列（重要顺序）**：
1. `GetFriendList` 拿全量 steamid
2. `GetPlayerSummaries` 分批（100/批）拿昵称、头像、可见性
3. **过滤掉可见性 ≠ 3 的** —— 这些人的 `GetOwnedGames` 一次都不用发
4. 对剩下的逐个 `GetOwnedGames?appids_filter=548430`，并发数用常量 `FRIENDS_CONCURRENCY = 5`
5. 结果写缓存

错误判别：
- `bad_key`：任一请求收到 401/403 → 整页「这把 key 不被 Steam 接受」
- `offline`：网络错误或超时（15s）→ 有缓存用缓存 + 一行"没连上 Steam"
- 好友列表为空 vs 拿不到：`friendslist` 缺失 = 拿不到（多半是资料没公开）；`friendslist: {}` = 真的没好友

## §6 风险

1. **Steam 接口行为未经真 key 验证**：`GetFriendList` 在对方资料不公开时返回 401 还是空列表，社区说法不一致。处理策略是"两种都当拿不到"，无论实测结果如何代码都不变。
2. **隐藏 ≠ 报错**：`GetOwnedGames` 给的是 200 + 空对象，一旦写成"空=零游戏"，好友会被显示成没玩过任何游戏。单测必须覆盖这条。
3. **本机 Steam 路径**：`loginusers.vdf` 在非默认安装位置（装在 D 盘、改名）时读不到 → 已设计成三级回退，最后一档是手填。
4. **好友数上限**：每多一个好友多一次请求。并发常量 + 进度提示，不设硬上限；如果实测发现过慢，下一版再加"只查最近登录"的筛选。
