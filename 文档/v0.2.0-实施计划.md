# v0.2.0 实施计划：存档解析地基（只读）

> **依据**：`文档/路线图-v0.1到v1.0.md` §4「v0.2.0 存档解析地基」、§6「伴侣线排期」
> **这一版只证明一件事**：在不毁档的前提下，这份存档我们能读懂多少。
> **形状**：数据层读七块 · 页面只放几个数字 · 七块的细节进开发者视图 · 天赋排到 v0.2.2

---

## 0. 决策（已拍板，执行方不要再问）

| # | 事项 | 定论 |
|---|---|---|
| 1 | 这版边界 | **数据全量、页面最小**。七块的数据层这版全做，用户界面上只放概览 |
| 2 | 页面放什么 | 总蓝等、金币、总时长（局数），总共四五个数字。**不加料**——加两个数字就会想加卡 |
| 3 | 页面底部一行 | 「已读到 N 块，其中 M 块的数据还没做界面」。N/M 由解析结果实算，不写死 |
| 4 | 天赋 | **数据层这版读**，页面不做；整个天赋面板（含星星）排到 **v0.2.2**，与职业进度同版 |
| 5 | 「只读」怎么保证 | 先流式算 sha256 → 复制副本 → 只解析副本 → 解析完再算一次原档哈希比对，不一致中止 |
| 6 | 槽位怎么选 | 页面顶部**一条下拉**，默认选中最近修改的；备份文件折叠在「显示备份」开关后 |
| 7 | 多个 Steam 账号 | 只列当前账号的，其余折叠成「还有 N 个别的账号的存档」 |
| 8 | 存档位置 | 只扫两个候选：`%LOCALAPPDATA%\FSD\Saved\SaveGames\<SteamID>\`、`Steam\userdata\<账号>\548430\`。**这两个之外不做任何递归搜索** |
| 9 | 找不到档 | 三种状态分开：没找到 / 格式不认识 / 版本没适配。各一句人话 + 一个动作 |
| 10 | 解析失败兜底 | **宽容**：能读多少读多少，顶部标「有 N 项没读出来」，不假装全读到 |
| 11 | 一键备份 | **做**。设置页一个按钮，复制当前选中的档到用户指定目录，带时间戳。只在用户点的时候做 |
| 12 | 名称对照表 | 一份 `names.json`；职业 / 资源 / 超频先填实，其余显示 `#id` |
| 13 | 资源抽取 | **不绑发布**。做完就并入，若已发布则进 v0.2.1 |
| 14 | 抽取失败时 | 显示 `#id` + 一行说明，不整块隐藏 |
| 15 | 开发者视图 | **算产品功能**：要有空态、要进回归、能在设置里开关。不进用户文档 |
| 16 | 缓存 | 同一份档 sha256 相同就复用上次解析结果，不重复复制与解析 |
| 17 | 解析器 | 自己写，不引第三方 GVAS crate |
| 18 | M0 单独交 | M0 交付后才开工写产品代码 |

## 1. 现状与事实（已查明，不必重查）

**样本**：`D:\steam\userdata\1066796681\548430\` 下共 24 个 `.sav`；主档 `76561199027062409_Player.sav` **454,223 字节**；`_Backup_0..3` 与 `_Player_ExternalBackup_0..3` 各约 454 KB。

**本机没有本地存档目录**：`%LOCALAPPDATA%\FSD\Saved\SaveGames` 不存在——游戏没在本账户下跑过，云缓存是唯一副本。所以两条路径都得实现，不能只写一条。

**格式**：UE4 标准 GVAS 容器（魔数 + 版本 + 自定义版本 + 属性树），未压缩。

**字段确认度**：① 职业、② 资源、③ 超频 三块已确认到结构；④ 武器模组、⑤ 外观、⑥ 进度、⑦ 天赋 只到字段名，结构待 M0 摸。

## 3. 里程碑

### M0 · 只读取证与样本固定（1 天，单独交付）

三份东西齐了才算完：

1. `_tools/save-samples.md`：样本清单 + 每个文件的 sha256（样本本体放 `_tools/save-samples/`，不进仓库）
2. `_tools/save-fields.md`：七块逐字段——路径 / 类型 / 含义 / 是否确认
3. 一份**能跑出七块内容的探查输出**

判据：④⑤⑥⑦ 每块要么「结构已打出并写明字段路径」，要么明确写「这块没跑通，原因是 X」。**允许不完整，不允许含糊。**

### M1 · GVAS 读取器（1.5 天）

- 容器层：`GVAS` 魔数、版本、自定义版本、包名、引擎版本
- 属性树：`FPropertyTag` 全支持（类型名、大小、数组下标、GUID、结构体、Map）
- 优先类型：`Int` / `Int64` / `Float` / `Str` / `Bool` / `Name` / `Array` / `Map` / `Struct`
- 不认识的属性**靠 tag 里的 `size` 跳过**，并记一条「跳过：<路径>」——这就是决策 10 的 N
- 单测：喂样本断言关键值；喂**人为截断的文件**断言「格式不认识」而不是 panic

### M2 · FSDSaveGame 字段层与只读保证（1.5 天）

- 七个结构体：`MinerSave` / `Resources` / `SchematicSave` / `WeaponUpgradeSave` / `VanitySave` / `ProgressSave` / `PerkSave`
- 只读四步：`compute_sha256()` → `copy_to_cache()` → `parse_copy()` → `verify_sha256_again()`
- 缓存：`saves/<sha 前 16>.json`，命中即跳过复制与解析
- 单测：同档解析两次，第二次走缓存且结果一致；哈希不一致时中止并报「存档在读取过程中变了」

### M3 · 「我的数据」页（1 天）

- 导航：新增一页「我的数据」，放在「背包」之后、「设置」之前
- 顶部：一条下拉列出所有槽位（主档在前、备份折叠、其他账号折叠），**默认选中最近修改的**，页面打开就有数
- 中间：四个数字——总蓝等、金币、总时长、局数
- 底部：一行「已读到 N 块，其中 M 块的数据还没做界面」
- 四态齐全：加载中 / 没找到存档 / 格式不认识 / 版本没适配，各配一个动作
- 设置页：一键备份按钮（决策 11）

### M4 · 名称对照表（0.5 天）

- `app/src/data/names.json`：职业 / 资源 / 超频 三块填实，其余块铺骨架
- 缺失条目显示 `#id` + 一行说明

### M5 · 资源抽取（不卡发布，1–3 天，可延后）

- 从 `.uasset` 抽 `id → 中文名`，产物写成与 `names.json` 同一格式
- 谁先到谁生效；彻底失败也不影响发布

### M6 · 开发者视图与回归（1 天）

- 设置页开关「显示原始字段」，打开后「我的数据」页多一张表：字段路径 / 类型 / 原始值
- 开关状态**不写进 UI 状态持久化**（避免用户下次打开莫名其妙看到内部名）
- 回归补：七块有数据、切档生效、显示备份开关生效、坏档报对错误、开发者视图可开关、备份生成的文件能被识别
- 单测覆盖：GVAS 各类型、截断文件、缓存命中、哈希不一致中止

## 4. 验收（能演示的）

- [ ] 用 `_Player.sav` 读出七块数据，开发者视图能逐块展开
- [ ] **原档 sha256 操作前后完全一致**（贴两次哈希）
- [ ] 概览页四个数字有值，底部那行 N/M 与实际解析结果对得上
- [ ] 切换槽位，数字跟着变
- [ ] 人为截断一个 `.sav`，界面报「格式不认识」，不崩、不静默出空
- [ ] 点一键备份，生成的副本大小与原档一致
- [ ] 开发者视图能列出原始字段名与值；关掉后界面上不出现 `OwnedSchematics` 这类内部名
- [ ] 回归全绿 + 单测通过数写进报告

---

## 5. 不做

- 不改存档、不"修复"存档、不提供任何写原档的按钮（备份是复制）
- 不做看板式分区、不做职业/武器/外观/进度的界面（v0.2.1 起）
- 不做天赋面板与星星计算（v0.2.2）
- 不做云同步、多设备
- 不做自动轮询发现新存档；进页面扫一次 + 手动刷新
- 不做星空/壁纸/主题

## 7. 风险

| 风险 | 概率 | 应对 |
|---|---|---|
| ④⑤⑥⑦ 的属性树比预期复杂 | 中 | M0 先摸；摸不清的块只写进字段表，不进代码 |
| 「总时长 / 局数」字段找不到 | 中 | 少显示一个数字，不猜、不估算 |
| 玩家存档被别的工具同时写 | 低 | 二次哈希比对直接抓住并中止 |
| 抽取拖成无底洞 | 中 | 决策 13 已解耦，M5 可以整个砍掉 |
| 用户以为我们改了档 | 低 | 页面常驻一行「只读不写」+ 一键备份做退路 |
