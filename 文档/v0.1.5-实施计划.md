### Q15 的依据（为什么不是「不改，写进文档」）

三个选项摆出来过：① 文档写清、② 卸载器删、③ 把缓存改存进数据目录。选 ② 的理由：

- ① 是拿文案补代码。装一次卸一次就永久留 80 MB，而这个软件号称「卸载不动你的数据、也不在你的机器上留东西」，第一条成立，第二条不成立。
- ③ 更根治，但 Tauri 2 的 `windows[].dataDirectory` 只接受**相对路径**，一律拼到 `%LOCALAPPDATA%\<label>\` 下（`tauri-2.12.5/src/webview/mod.rs:398-424`）。真要挪进 `data\`，得放弃配置式建窗、改成代码里 `WebviewWindowBuilder::data_directory()`（同文件 `:1040` 支持绝对路径）——动的是首启路径，失败表现是白屏，风险和「删缓存」不在一个量级。缓存该不该跟文件夹走，是 v0.1.6「轻便」要回答的问题。

### Q13 的依据（为什么不能用 localStorage）

「记住上次停留的页」和「引导卡已收起」要跨重启保留。WebView2 的用户数据目录默认在 `%LOCALAPPDATA%`，用 localStorage 会让这两项留在 C 盘，便携模式下 U 盘换台机器就丢，违反「配置跟文件夹走」。所以走 `paths::data_root()`，数据目录跟随 exe。

读写失败一律回落到「今天」，不弹错、不白屏。

## 1. 现状事实（只读核查，2026-10-30）

**能直接复用的**

- `src-tauri/src/cache.rs:25-29` 有 `Fresh<T> { cached_at, value }`，文件式 JSON，根目录 `<数据目录>\cache\`，没有 TTL——正好用来判"是不是今天的"
- `src-tauri/src/modio.rs:193-198` 有 `reqwest::Client`（timeout 90s / connect_timeout 20s），`:388-435` 的 `send()` 统一处理 401/403/404 与 429 重试
- `src-tauri/src/paths.rs:119-121` 已有 `modio-token.txt` 的读写，令牌有无可直接判断
- `src/App.tsx:102` 三页常驻 DOM、用 `hidden` 切换，切页不丢状态

**三条绕不开的限制**

1. **前端完全不联网**：全 `src/` 搜 `fetch` / `XMLHttpRequest` / `axios` 零命中；`tauri.conf.json` 的 `csp` 是 `null`，也没有 `plugin-http`。抓 Steam 公告**必须写在后端**
2. **mod.io 不带令牌读不到任何东西**：`/v1/games/2475` 与 `/v1/games/2475/mods` 都是 401（`malformed/missing api_key`）。所以 mod 动态块天然依赖令牌
3. **仓库里的分页/排序参数是下划线前缀**：`modio.rs:247` 用 `_limit` / `_offset` / `_sort`，`:290` 用 `_sort=-date_added`。**不是** `sort`、`limit`

**Steam 公告接口实测（2026-10-30）**

- `GET https://api.steampowered.com/ISteamNews/GetNewsForApp/v2/?appid=548430&count=5&maxlength=300` → **200，3.5 KB，0.11 秒**
- 顶层只有 `appnews`，内含 `newsitems` 与 `count`；**`count` 是库里总数（实测 581），不是本次返回条数**，不要拿它做分页
- 每项 11 个字段，我们只要 5 个：`gid`、`title`、`url`、`date`（Unix 秒）、`contents`
- **`contents` 的格式由 `maxlength` 决定**：`maxlength=300` 返回**纯文本**（标签和换行都被剥掉）；`maxlength=0` 返回 **BBCode**（含 `[h1][p][url][img]`）。我们只要摘要，用 300 这一档
- **没有中文**：5 条 title + contents 的 CJK 命中为 0；加 `&l=schinese` 返回字节完全相同（md5 一致），说明这个 feed 不受语言参数影响。这正是 Q5 选「只显示原文」的事实依据

## 3. 里程碑

### M5-0 · 前置核对（0.5 天）

三条核对，结论决定后面怎么写：

1. **本地记账里有没有 mod 版本号**：`list_installed` 返回的条目里若有 `version` 字段，第 ③ 块才能做「有新版」；没有就降级为"列出你装的 mod 与安装时间"，并在回报里写明降级原因
2. **带令牌时 `_sort=-date_updated` / `_sort=-date_added` 是否被接受**：无令牌全是 401，参数对错验证不了，必须带真令牌试一次
3. **Steam 公告在目标机器可达性**：这台机器通不代表用户通；这一条不改设计，但决定离线回退必须做扎实

**验收**：三条各一句话结论 + 证据（命令输出或代码行号）。

### M5-1 · 后端取数（1.5 天）

- 新建 `src-tauri/src/steam.rs`：`fetch_news(appid, count, maxlength) -> Vec<NewsItem>`，只取 `gid / title / url / date / contents`
- 新建 `src-tauri/src/ipc/today.rs` + 命令 `today_digest`，返回：

```
TodayDigest {
  fetched_at:   u64,
  from_cache:   bool,
  news:         Vec<NewsItem>,    // 最多 3 条
  mod_changes:  Vec<ModChange>,   // 最多 6 条，新上架与更新混排，带 kind
  updates:      Vec<ModUpdate>,   // 最多 10 条
  token_missing: bool,
  degraded:     Vec<String>,      // 哪几块失败，如 ["news"]
}
```

- 三块**分别取、分别降级**，任何一块失败都不让整个命令失败
- 写 `cache\today.json`；命令开始时若缓存 `fetched_at` 是**当天**（按本地日期比较）就直接返回并置 `from_cache = true`
- 复用 `modio.rs` 的 client 与错误处理，不新写 HTTP 层，**不新增依赖**

**验收**：断网时返回 `Ok`（含缓存内容与 `degraded`），不是 `Err`；无令牌时 `token_missing=true` 且 `mod_changes` 为空数组。

### M5-2 · 前端「今天」页（1.5 天）

- `src/pages/Today.tsx`，页头一行标题 + 右上角一个刷新按钮
- 三块顺序按 Q4：**有更新时**更新块置顶，否则按 公告 → 新 mod（更新块仍在，写「你装的 mod 都是最新的」）
- 三块条数按 Q10：公告 3、新 mod 6、更新最多 10
- 数据回来前是骨架块（Q7），不得等网络才渲染
- 令牌缺失时：首次显示引导卡（一句话 + 一个「去设置」按钮），点过之后收成一行小字「粘个令牌就能看到 mod 动态」，可再次展开（Q2）
- 公告项点击：`open_url` 打开 Steam 页，**只放行 http / https**

**验收**：见 §4。

### M5-3 · 导航、默认页与记忆（0.5 天）

- `src/App.tsx` 的 `NAV` 增加「今天」，**放在最上面且不属于「矿层」组**（Q8）
- `src/store/appStore.tsx` 的 `page` 初值改为「今天」；若有 `ui-state.json` 则恢复上次的页
- 每次切页写回 `ui-state.json`（防抖，不必每点一次就落盘）
- 保留三页 + 今天页常驻 DOM、用 `hidden` 切换的机制，不改卸载重挂

**注意**：这条会让现有回归里"默认落在矿脉"的断言失效，M5-5 统一处理。

### M5-4 · 引导卡收起状态（0.5 天）

- `ui-state.json` 增加 `tokenHintCollapsed`
- 首次进入「今天」且无令牌 → 卡片；点过收起或粘过令牌 → 一行小字
- 收起状态跨重启保留

**验收**：连开两次，第二次不再出现整张卡片。

### M5-5 · 验收与回归（1 天）

- 新增回归场景至少 5 条：① 无令牌时第 ② 块是引导卡 ② 收起后重启仍是一行小字 ③ 断网显示缓存并标「离线」 ④ 公告项点击只放行 http/https ⑤ 三块任一失败不影响另外两块
- Q6 的验证：把 `cache\today.json` 的 `fetched_at` 改成前天（内容换成另一批假数据），重启看是否重取并换内容
- 截图基线 `before-015` / `after-015`
- 性能：冷启动仍 < 1.5 秒；**新增的网络请求不得进入首屏关键路径**
- 版本号三处改 `0.1.5`；出安装包与便携包；写 CHANGELOG

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 用户网络到 Steam 不通 | 公告块常空 | 缓存回退 + 失败只影响一块，页面不写"网络错误"这种废话 |
| 新用户没令牌 | mod 动态块长期空 | 引导卡收成一行，不天天整张糊脸 |
| 首屏被拖慢 | 违反「快捷」宗旨 | 骨架先出、请求异步；验收单列这条 |
| 默认页变了，回归断言失效 | 回归红灯 | M5-3 已写明，M5-5 统一改 |
| 公告全是英文 | 中文用户看不懂 | 这是 v0.1.6 的事，这版不硬凑；Q5 已定只显示原文 |
| `ui-state.json` 写坏 | 启动白屏 | 读失败一律回落到「今天」，不弹错 |

## 8. 交给执行方的边界

- 现有 30 个命令签名一个不改，只**新增** `today_digest` 一条
- 不新增任何依赖（`reqwest` 已有，Steam 返回 JSON，现有 `json` feature 够用）

- 提交用显式路径，不许 `git add -A` / `git add .`
- 每版发布前给一份「实际做了什么」，由计划侧写 CHANGELOG
